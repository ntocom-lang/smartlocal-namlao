# ประวัติค่าอ่างเก็บน้ำ — ฤดูแล้ง (เฟส 5 · PR 5.1 ฐานข้อมูล)

> เจ้าของระบบสั่ง 2569-10-18: ขอบเขตคือ **รัศมี 10 กม. เน้นต้นน้ำ ทางน้ำที่ไหลมาหาพื้นที่เรา**
> PR 5.1 = เริ่มเก็บค่าอ่างย้อนหลังนานขึ้น (เร่งเวลา: ย้อนเก็บทีหลังไม่ได้) · PR 5.2 = การ์ด "ต้นน้ำ" บนหน้าสาธารณะ (ยังไม่ทำ)

## ทำไม

`water_readings` ลบทุกอย่างที่เก่ากว่า 7 วัน ค่าอ่างจึงมีย้อนหลังแค่ 6–7 วัน — ดูแนวโน้มทั้งฤดูแล้งไม่ได้ และต้นทาง (ThaiWater/กรมชลประทาน) ส่งแต่ค่าล่าสุด
ย้อนเก็บทีหลังไม่ได้ จึงต้องเริ่มเก็บก่อนฤดูแล้ง (เหตุผลเดียวกับตัวจดเหตุการณ์ — ดู `water-events.md`)

## นโยบาย (ค่าอยู่ที่ฟังก์ชัน `water_dam_history_radius_km()` / `water_dam_history_keep_days()` ที่เดียว)

| เรื่อง | ค่า | หมายเหตุ |
|---|---|---|
| เก็บยาว | เฉพาะ `station_type = 'dam'` ที่ `distance_km ≤ 10` | วัดเส้นตรงจากสำนักงาน ไม่ใช่ระยะตามลำน้ำ · ไม่มีระยะ (NULL) = ไม่เก็บยาว |
| ระยะเวลา | 400 วัน | อ่างส่งรายวัน 1 วัน = 1 แถว → ~400 แถว/สถานี (< 1 MB ต่อปีทั้งระบบ) |
| ที่เหลือ | ลบที่ 7 วันเหมือนเดิม | ฝน · ระดับน้ำ · เตือนภัย (ews) · ข้อความเตือน · อ่างนอกรัศมี |

ไม่ผูกกับ `is_active` — อ่างที่ปิดใช้งานแต่อยู่ในรัศมีก็ยังเก็บ (ไม่ทำให้ประวัติขาดถ้าเปิดกลับ)

## ฟังก์ชันอ่าน `get_public_dam_history(_municipality_id, _days = 30)`

- หน้าสาธารณะ (anon + authenticated) · บังคับระบุ อปท. · NULL / ไม่รู้จัก / อปท. ปิดใช้งาน → NULL · อปท. ที่ไม่มีอ่างในรัศมี → `dams: []`
- เฉพาะอ่างที่ `is_active` และอยู่ในรัศมี เรียงใกล้→ไกล · `_days` ครอบ 1..120 (กัน egress บวม)
- ค่าว่างไม่ปรากฏ (ไม่เป็น 0) · ค่า 0 จริงยังเป็น 0 · หน่วยตามต้นทาง ปริมาณเป็นล้าน ลบ.ม.
- **ไม่บอกว่าอ่างไหนคือ "ต้นน้ำ"** — พิกัดบอกระยะ ไม่บอกทิศน้ำไหล ทะเบียน "ต้นน้ำที่ยืนยันแล้ว" รายตำบลอยู่ฝั่งหน้าเว็บ (PR 5.2)

## ต้นน้ำที่ยืนยันได้ตอนนี้ (หลักฐาน = ผังศูนย์ฯ แพร่ ที่เราวาดไว้ใน `src/lib/waterDiagram/`)

| อปท. | อ่างในรัศมี 10 กม. | ต้นน้ำที่ยืนยันแล้ว |
|---|---|---|
| น้ำเลา (+ demo) | แม่คำปอง 3.6 · แม่ถาง 4.3 | **แม่คำปอง** (ผังน้ำเลา: ต้นน้ำแม่คำปอง ไหลเหนือ→ใต้ลงลำน้ำแม่ถาง) · แม่ถางยังไม่ยืนยัน (อยู่ ต.บ้านเวียง ผังไม่ได้วาดตัวอ่าง) |
| ตำหนักธรรม | ไม่มี (10.2 / 11.2 กม. เกินรัศมี) | ไม่มี |
| ทุ่งแค้ว | ไม่มีอ่าง | ไม่มี |

## ตำหนักธรรม: ปิดอ่างแม่คำปอง/แม่ถาง (20261018100200)

เจ้าของระบบ: "ถ้าไม่ไหลผ่านตำหนักธรรม ก็ไม่จำเป็นสำหรับตำหนักธรรม" — ผังทั้งสองฉบับไม่ระบุว่าน้ำจากอ่างนี้ไหลผ่านน้ำแม่คำมี/ตำบล
และค้นเว็บแล้วไม่พบเส้นทางลำน้ำ จึงถือว่ายังไม่ไหลผ่านจนกว่า อบต. จะยืนยัน → ปิดที่ `water_station_config.is_active` (เหมือน Y.38 ของน้ำเลา `20260928100000`)
ทุกช่องทาง (หน้าเว็บ · แถบหน้าแรก · Telegram · ตัวจดเหตุการณ์) อ่านเฉพาะสถานีที่เปิดใช้ จึงตัดสินตรงกัน

**ถ้า อบต. ยืนยันว่าไหลผ่าน:** `UPDATE public.water_station_config SET is_active = true ...` (เงื่อนไขเดียวกับไฟล์ปิด) — แต่ค่าอ่างจะเริ่มเก็บยาวไม่ได้เพราะอยู่นอกรัศมี 10 กม. ต้องตัดสินใจเรื่องรัศมีด้วย

**คำถามที่ส่งให้ อบต.ตำหนักธรรม / ศูนย์บริหารจัดการน้ำ จ.แพร่ / ชลประทาน:**
> "อ่างเก็บน้ำแม่คำปอง (ต.น้ำเลา) และอ่างเก็บน้ำแม่ถาง (ต.บ้านเวียง) อ.ร้องกวาง ส่งน้ำหรือไหลผ่านน้ำแม่คำมี/ตำบลตำหนักธรรมหรือไม่"
> และ (น้ำเลา) "อ่างแม่ถางอยู่ต้นน้ำของตำบลน้ำเลาหรือไม่"

## ผลข้างเคียงที่ตรวจแล้ว

- `get_public_water_situation` นับ "ตัวเลขอ่างซ้ำเดิมกี่รายงาน" (`dam_same_count`) จากแถวอ่างที่เก็บไว้ทั้งหมด → เก็บนานขึ้นทำให้นับได้เกิน 7 และ `dam_same_capped` จริงน้อยลง
  (ความหมายถูกต้องกว่าเดิม ไม่ได้เปลี่ยน) · ข้อความ "ซ้ำเดิมมาอย่างน้อย N วัน" ในโค้ดยังถูกต้อง
- `water-alert-notify` / `thaiwater-watchdog` / ตัวจดเหตุการณ์ ดึงเป็นช่วงสั้น (3 วัน / ล่าสุด / 24 ชม.) ไม่กระทบ
- `thaiwater-sync` ไม่รับค่าที่เก่ากว่า 7 วัน (ไม่ backfill) — ไม่เกี่ยวกับนโยบายนี้
- ⚠️ ฟังก์ชัน `cleanup_old_water_readings()` ถูกเขียนทับทั้งตัว (CREATE OR REPLACE) — เทียบกับตัวบน production แล้วตรงกับ `20260919100300` ก่อนเขียนทับ
