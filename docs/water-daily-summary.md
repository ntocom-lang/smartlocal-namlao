# สรุปรายวันของสถานีน้ำ-ฝน (ฐานข้อมูลของอินโฟกราฟิก "สรุปสถานการณ์น้ำ–ฝน" วัน / สัปดาห์ / เดือน / ปี · PR A)

เจ้าของระบบสั่ง 2569-10-19: ทำอินโฟกราฟิก "สรุปสถานการณ์น้ำ–ฝน" ไว้แชร์ให้ประชาชน แบบรายวัน สัปดาห์ เดือน ปี บนกระดาษ A4 ใบเดียว
แผน 3 PR (อนุมัติ "ตามแนะนำ"): **A = ฐานข้อมูลเก็บสรุปรายวัน (ไฟล์นี้)** → B = ใบ A4 + ภาพ แบบวัน/สัปดาห์ → C = แบบเดือน/ปี + ปุ่มบนหน้าเว็บ
PR นี้ **ไม่มีหน้าจอ ไม่มีสิ่งใดออกสู่ประชาชน ไม่มี Edge Function ไม่มี secret** — เก็บข้อมูลอย่างเดียว ย้อนเก็บทีหลังไม่ได้ จึงต้องทำก่อน

## ทำไมต้องมี

`water_readings` ลบทุกอย่างที่เก่ากว่า 7 วัน (`cleanup_old_water_readings` 18:45 UTC = 01:45 น. ไทย ทุกคืน) ยกเว้นอ่างในรัศมี 10 กม. ที่เก็บ 400 วัน (PR 5.1)
ฝนกับระดับน้ำจึงมีย้อนหลังแค่ 7 วัน → สรุปรายเดือน/รายปีทำไม่ได้ และต้นทางส่งแต่ค่าล่าสุด ย้อนเก็บไม่ได้ — **ทุกวันที่ช้า = ข้อมูลของปีนี้ที่หายไปตลอดกาล**
ตรวจจริง 2569-10-19: ข้อมูลฝน/ระดับน้ำเก่าสุด 12 ต.ค. 00:00 (ไทย) · ตารางเหตุการณ์ (`water_events`) ยังมี 0 แถว

## ⚠️ ข้อห้ามสำคัญ: ห้ามบวกรวมฝนสะสม 24 ชม. เป็น "ฝนรวมเดือน/ปี"

`rain_24h_mm` ของต้นทาง **ขึ้น–ลงเองตลอดวัน** ไม่ใช่ตัวนับที่ไม่ลด (ตรวจจริง STN0911 ในวันเดียว 3.5 → 2.5 → 2 → 1 → 2.5 มม.)
บวกรายวันหรือรายชั่วโมงจะเกินจริงหลายเท่า — ตารางนี้จึงเก็บแค่ "สูงสุดของวัน" (+ เวลา) · สรุปรายเดือน/ปีให้ใช้
- ค่าสูงสุดที่เคยพบในช่วง (สถานีไหน วันไหน)
- จำนวนวันที่ค่าสูงสุดถึงระดับที่กำหนด (ใช้เกณฑ์ระดับฝนเดิมของหน้า `src/lib/waterSituation.js` ไม่คิดเกณฑ์ใหม่)

ถ้าอยากได้ "ฝนรวม" จริง ต้องเปลี่ยนแหล่งข้อมูลเป็นรายงานฝนรายวันของต้นทาง (ยังไม่มีในระบบ) — ไม่ใช่ทำจากค่านี้

## ระบบทำอะไร

`water_daily_summary_tick(_now, _days_back)` รันทุกชั่วโมง **นาทีที่ 30** (sync :10 → แจ้งเตือน :15 → ตัวจดเหตุการณ์ :20 → ตัวร่างประกาศ :25 → ตัวนี้) อ่านจากฐานข้อมูลเราเท่านั้น
- สรุป **วันนี้และ 2 วันก่อนหน้า** (วันไทย) ของสถานี **ฝน / ระดับน้ำ / อ่าง** ของ อปท. ที่เปิดโมดูลน้ำ-ฝน (เหมือนตัวจดเหตุการณ์) → upsert ลง `water_daily_summary` · รันซ้ำผลเท่าเดิม · วันที่ยังไม่จบค่อยๆ ครบขึ้นทุกชั่วโมง
- ย้อน 2 วันเผื่อรอบที่พลาด/ต้นทางส่งค่าล่าช้า (ข้อมูลดิบเก็บ 7 วัน จึงมีครบเสมอ)
- **ไม่เขียนทับแถวที่ครบกว่าด้วยแถวที่ขาดกว่า** (แทนเมื่อจำนวนค่าที่วัดได้ใหม่ ≥ เดิม) — กันกรณีสั่งย้อนหลังเกินหลังข้อมูลดิบถูก cleanup ไปแล้ว · **ฟังก์ชันไม่ลบแถวใดเลย**
- ไม่สรุปสถานีเตือนภัย (ews) · ไม่สรุป อปท. ที่ปิดโมดูล/ปิดใช้งาน · ค่าที่เวลาวัดอยู่หลังเวลาของรอบไม่ถูกนับ
- ลง `job_heartbeats` ชื่อ `water-daily-summary-tick` · อปท. หนึ่งพังไม่ลากรอบของแห่งอื่นล้ม
- **ตอน apply ย้อนเติมจากข้อมูลดิบที่ยังมี (8 วันล่าสุด)** — เร่ง apply ให้ทันก่อน cleanup รอบถัดไป (ลบวันที่เก่าสุดทิ้งทุกคืน)

## ตาราง `water_daily_summary` (ปิดสนิท: RLS เปิด ไม่มี policy ถอนสิทธิ์ anon/authenticated ทั้งหมดรวม TRUNCATE)

1 แถว = 1 สถานี × 1 วัน (วันไทย) · คีย์ (`municipality_id`, `station_type`, `station_code`, `day`) · ≈ 10 สถานี × 365 วัน ≈ 3,650 แถวต่อปีต่อ อปท. (ไม่ถึง 1 MB)

| กลุ่ม | คอลัมน์ |
|---|---|
| ทั่วไป | ชื่อสถานี · ระยะ (กม.) · is_primary (สำเนา ณ รอบล่าสุด ไม่ผูก FK — ลบ/ปิดสถานีแล้วสรุปเก่าไม่หาย) · `readings_count` (วันนั้นข้อมูลครบแค่ไหน) · เวลาค่าแรก/สุดท้าย |
| ฝน | `rain_24h_max_mm` + เวลา · `rain_1h_max_mm` + เวลา |
| ระดับน้ำ | `bank_diff_min_m` + เวลา (ใกล้ตลิ่งสุด · บวก = ต่ำกว่าตลิ่ง **ลบ = ล้นตลิ่ง ไม่ถูกตัดเป็น 0**) · `waterlevel_max_msl` + เวลา · `waterlevel_min_msl` |
| อ่าง | ปริมาตร/ความจุ/% ของ **ค่าสุดท้ายที่ไม่ว่างของวัน** (อ่างส่งรายวัน 1 วัน = 1 ค่า) |

- วันของค่า = วันตามเวลาไทยของเวลาที่สถานีวัด (23:59 ไทยยังเป็นวันเดิม · ค่าอ่างรายวันลงเที่ยงคืนไทย = 17:00 UTC ของวันก่อน นับเป็นวันนั้น)
- **ค่าว่างไม่เป็น 0:** วันที่สถานีส่งแต่ค่าว่าง = มีแถวพร้อม `readings_count` แต่ช่องค่าเป็น NULL · วันที่ไม่มีค่าเลย = ไม่มีแถว
- ไม่เก็บชื่อ เบอร์ พิกัดของบุคคล (เทสต์ตรวจชื่อคอลัมน์)

## นโยบายเก็บ

**ยังไม่ลบอัตโนมัติ** (เหมือนตารางเหตุการณ์) — ขนาดเล็กมาก และไม่ทราบว่าระเบียบการเก็บรักษาเอกสารบังคับเก็บกี่ปี (**ต้องยืนยันกับฉบับปัจจุบัน** ก่อนเปิดลบอัตโนมัติ · ไม่ได้อ้างระเบียบใดไว้ในโค้ดหรือเอกสาร) · ทบทวนเมื่อฐานข้อมูลเกิน 300 MB

## สิ่งที่ยังไม่มี (PR ถัดไป)

- **ฟังก์ชันอ่านสาธารณะ** (`get_public_water_summary` หรือชื่อใกล้เคียง) + ใบ A4 + ภาพ PNG → PR B (วัน/สัปดาห์) และ PR C (เดือน/ปี)
- เดือน/ปีที่ข้อมูลยังไม่ครบ: ใบจะบอกตรงๆ ว่า "เก็บตั้งแต่ … " ไม่ทำให้ดูเหมือนเต็มช่วง · ข้อมูลเต็มปีจริงจะมีเมื่อ ต.ค. 2570 (เริ่มเก็บ ต.ค. 2569)
- `thaiwater-watchdog` ยังไม่เฝ้างานนี้ (เหมือนตัวจดเหตุการณ์) — ดูสถานะที่ `job_heartbeats` แถว `water-daily-summary-tick`

## ตรวจ/ดูข้อมูล (ฝั่ง SQL editor ของเจ้าของระบบ)

```sql
SELECT day, station_code, readings_count, rain_24h_max_mm, bank_diff_min_m, dam_storage_percent_last
FROM water_daily_summary WHERE municipality_id = (SELECT id FROM municipalities WHERE slug = 'namlao') ORDER BY day DESC, station_code;
SELECT * FROM job_heartbeats WHERE job_name = 'water-daily-summary-tick';
```
