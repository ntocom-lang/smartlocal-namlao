# ประกาศสถานการณ์น้ำ-ฝนของ อปท. ที่มีผู้ยืนยัน (เฟส 2 · PR 2.1 ฐานข้อมูล + PR 2.2 หน้าจอ)

## หลักการ (เส้นที่ห้ามข้าม)

การประกาศเตือนภัยเป็นดุลพินิจและอำนาจของผู้บริหารท้องถิ่น — **ระบบร่าง คนกดยืนยัน** ไม่มีคนกด = ไม่มีอะไรออก ระบบไม่ประกาศแทน ไม่สั่งอพยพ ไม่ประเมินความเสียหาย ไม่ตัดสินสิทธิ์ใคร

⚠️ **ผู้มีอำนาจประกาศตามกฎหมายและแผนป้องกันและบรรเทาสาธารณภัยของ อบต. ต้องยืนยันกับตัวบทฉบับปัจจุบันก่อนเปิดกับ อปท. จริง** (ไม่ได้อ้างเลขมาตราหรือชื่อกฎหมายไว้ในโค้ด/เอกสารนี้) — จึงปิดเป็นค่าเริ่มต้น เปิดทีละ อปท. เมื่อ อบต. ยืนยันแล้ว ทดสอบบน demo (สนามซ้อม) เท่านั้น

## ภาพรวม

1. **ระบบร่าง** — `water_announcement_tick()` (cron นาทีที่ 25 หลังตัวจดเหตุการณ์) ร่างข้อความจากค่าที่วัดได้ของเหตุการณ์ที่เปิดอยู่ เฉพาะ อปท. ที่เปิดใช้
2. **ผู้มีสิทธิ์ยืนยันตัดสิน** — เห็นร่างในหน้า "เหตุการณ์น้ำ-ฝน" (และแถวใน "ต้องทำตอนนี้" ของหน้าแรก) → กด "ยืนยันและเผยแพร่" (มีขั้นยืนยันซ้ำ) หรือ "ไม่ประกาศ"
3. **ประชาชนเห็น** — ประกาศขึ้นแทนแถบแจ้งเตือนดิบบนหน้าแรก (ทุกธีม) และบนสุดของหน้า /water-situation · ครบอายุหรือยกเลิก = หายเอง

## ใครยืนยันได้ (PR 2.2 เปลี่ยนจาก PR 2.1)

PR 2.1 ให้ผู้ยืนยัน = นายก/ปลัดในทะเบียนผู้ลงนามกลางที่ "มีบัญชี" — แต่ตรวจ production (2026-10-19) แล้ว **ผู้ลงนามนายก/ปลัดที่ active ของทุก อปท. เป็น "ชื่อกรอกเอง" ไม่มีบัญชีเลย (0 ราย)** ผู้ยืนยันจึงไม่มีใครกดได้ — เจ้าของระบบเลือกทางแก้ (2026-10-19):

- ตาราง **`water_announcement_approvers`** — admin ของ อปท. (หรือ superadmin) เลือกบัญชีเจ้าหน้าที่ **1–5 คน** เป็นผู้มีสิทธิ์ยืนยัน (ตั้งครั้งเดียว) พร้อมช่อง **"อ้างอิงอำนาจ"** (≤ 300 ตัวอักษร) ที่ อบต. กรอกเอง เช่น เลขที่คำสั่งมอบหมาย — ผู้พัฒนาไม่ได้เติมและไม่ได้อ้างระเบียบใดให้
- `can_approve_water_announcement(อปท.)` = บัญชีนั้นอยู่ในตาราง **และยังเป็น admin/officer/staff ของ อปท. นั้น** (ถูกลดบทบาท/ย้าย อปท. = หมดสิทธิ์ทันที แม้แถวยังอยู่) · **ไม่ดูทะเบียนผู้ลงนามอีกต่อไป** · superadmin/admin ทั่วไปไม่ได้สิทธิ์โดยตำแหน่ง
- ตั้ง/ถอนได้เฉพาะ admin ของ อปท. นั้นกับ superadmin (`set_water_announcement_approver`) · ทุกครั้งลง `audit_logs` (`action = update`, `metadata.kind = approver`, มีข้อความอ้างอิงและผู้ตั้ง) · รายชื่อที่เลือกได้ = admin/officer/staff ของ อปท. นั้น ส่งแค่ชื่อ ตำแหน่ง บทบาท (ไม่มีอีเมล/เบอร์)
- ข้อความ "อ้างอิงอำนาจ" เห็นเฉพาะ admin ในกล่องตั้งค่า — ไม่ขึ้นหน้าประชาชนและไม่ส่งไปหน้าเจ้าหน้าที่ทั่วไป
- ⚠️ ผู้มีอำนาจประกาศจริงเป็นไปตามกฎหมายและแผนของ อบต. เอง — ระบบแค่ให้ admin เลือกคนกด ไม่ตัดสินแทน · ยังไม่มีผู้ยืนยันสักคน = ระบบร่างข้อความไว้แต่ไม่มีใครเผยแพร่ได้ ประชาชนไม่เห็นอะไร (หน้าจอเตือน admin และเจ้าหน้าที่ว่ายังไม่ได้ตั้ง)

## ฟังก์ชันฐานข้อมูล

| ฟังก์ชัน | ทำอะไร |
|---|---|

| `approve_water_announcement(id, ชั่วโมง)` | ผู้มีสิทธิ์ยืนยัน → ขึ้นหน้าประชาชน · ค่าเริ่มต้น 24 ชม. สูงสุด 72 |
| `decline_water_announcement(id)` | เลือก "ไม่ประกาศ" (ไม่ร่างซ้ำเรื่องเดิม 12 ชม.) |
| `cancel_water_announcement(id)` | ยกเลิกฉบับที่เผยแพร่ → หายจากหน้าประชาชนทันที |
| `list_water_announcements(อปท., จำนวน)` | หน้าเจ้าหน้าที่อ่าน — ร่าง · ฉบับที่ใช้อยู่ · ประวัติ · `can_approve` · `can_manage_approvers` · `approvers_count` · ไม่ส่ง facts/ข้อความอ้างอิงอำนาจ |
| `get_public_water_announcement(อปท.)` | หน้าประชาชนอ่านเฉพาะฉบับที่ยืนยันแล้วและยังไม่หมดอายุ — ส่ง id · ข้อความ · เวลาเผยแพร่/หมดอายุ · ชื่อ อปท. · `server_now` (ไม่ส่งชื่อผู้ยืนยัน) |
| `water_announcement_todo(p_muni)` | หน้าแรกเจ้าหน้าที่ถามว่า "มีร่างรอฉันยืนยันไหม" — ตอบจริงเฉพาะผู้ยืนยัน ที่เหลือได้ค่าคงที่ `{can_approve:false, pending:false}` |
| `list_water_announcement_approvers` / `set_water_announcement_approver` / `can_manage_…` | ตั้ง/ถอนผู้ยืนยัน (admin/superadmin) |

## ข้อความร่าง

ค่าที่วัดได้ล่าสุดของสถานีที่ทำให้ระบบเปิดเหตุการณ์ + เวลาวัด (เวลาไทย พ.ศ.) + "ไม่ใช่การพยากรณ์"

- **ไม่มีข้อความ "ควรทำอะไร"/อพยพ/รับรองความปลอดภัย** จนกว่า อบต. ให้ข้อความตามแผนของตน (เทสต์ห้ามคำเหล่านี้ในตัวสร้างข้อความ)
- ค่าว่างไม่กลายเป็น 0 (ค่า 0 ที่วัดได้จริงยังพูดว่า 0) · ใช้เฉพาะค่าที่วัดภายใน 3 ชม. · ไม่มีค่าสดเลย = ไม่ร่าง
- ร่างเฉพาะตอนสัญญาณยังเข้าเกณฑ์ในรอบตรวจล่าสุด (เหตุการณ์กำลังสงบ/ตัวจดหยุด = ไม่ร่าง)
- ข้อความเตือนของ สสน. บอกเพียงว่ามี + เวลา ให้ดูฉบับเต็มที่หน้าสถานการณ์น้ำ-ฝน (ไม่คัดลอกข้อความหน่วยงานอื่นเข้าประกาศของ อปท.)
- สถานีเกิน 6 แห่ง → "และสถานีอื่นอีก N แห่ง"
- ร่างอายุ **3 ชม.** (เกินนี้ถูกทิ้ง กดยืนยันไม่ได้ ระบบร่างใหม่ด้วยค่าล่าสุด) — ตัวเลข 3 ชม. อยู่ที่ SQL 3 จุดกับ `DRAFT_LIFE_HOURS` ในหน้าเว็บ เทสต์เทียบให้

## สถานะของประกาศ

`draft` ร่างรอยืนยัน → `published` เผยแพร่ → `expired` ครบอายุ / `cancelled` ยกเลิก / `superseded` ถูกฉบับใหม่แทน · `declined` เลือกไม่ประกาศ · `lapsed` ร่างที่ไม่ได้ใช้ (เก่าเกินอายุ/เหตุการณ์สิ้นสุดก่อนมีคนยืนยัน — ไม่เคยขึ้นหน้าประชาชน)

- หน้าประชาชนตัดสินจาก `expires_at` เอง **ไม่ต้องรอ cron** และนับด้วยนาฬิกาของฐานข้อมูล (`server_now` ปรับกับนาฬิกาเครื่อง) — เครื่องผู้ใช้ตั้งเวลาเพี้ยน (เร็ว/ช้า 3 ชม.) ก็แสดง/ซ่อนถูก
- ฉบับที่เผยแพร่เหลือเวลา < 3 ชม. และเหตุการณ์ยังเข้าเกณฑ์ → ร่างฉบับต่ออายุให้ยืนยันใหม่ (ยืนยัน = ฉบับเดิมถูกแทนในธุรกรรมเดียว) · ต่ออายุโดยแก้เวลาตรงๆ ไม่ได้
- ร่าง/ฉบับเผยแพร่ ซ้อนได้ทีละ 1 ต่อ อปท. (unique index ที่ฐานข้อมูล)

## หน้าจอ (PR 2.2)

**เจ้าหน้าที่ — ส่วน "ประกาศน้ำ-ฝนของหน่วยงาน"** เหนือรายการเหตุการณ์ในหน้า "เหตุการณ์น้ำ-ฝน" (`WaterAnnouncementsSection.jsx`)

| ใคร | เห็น/ทำได้ |
|---|---|
| อปท. ที่ไม่ได้เปิดประกาศ · ไม่มีสิทธิ์ดู · ฟังก์ชันยังไม่พร้อม | **ไม่เห็นอะไรเลย** (หน้าเดิมไม่เปลี่ยน) · โหลดพลาดจริง (เช่น timeout) = ข้อความเตือนเล็กๆ ส่วนเหตุการณ์ยังใช้ได้ |
| เจ้าหน้าที่ทั่วไป (ไม่ใช่ผู้ยืนยัน) | **อ่านอย่างเดียว ไม่มีปุ่มเลย** — เห็นร่าง/ฉบับที่ใช้อยู่/ประวัติ และข้อความ "รอผู้มีสิทธิ์ยืนยัน เจ้าหน้าที่คนอื่นไม่ต้องทำอะไร" (ไม่เพิ่มงาน) |
| ผู้มีสิทธิ์ยืนยัน | ร่างสด (< 3 ชม.): "ยืนยันและเผยแพร่" → **ขั้นยืนยันซ้ำ** ("เผยแพร่เลย"/"ยังก่อน") · "ไม่ประกาศ" · ฉบับที่เผยแพร่อยู่: "ยกเลิกประกาศนี้" → ขั้นยืนยันซ้ำ · ร่างเก่าเกิน 3 ชม. ไม่มีปุ่ม · ผลที่ทำไม่ได้ (เหตุการณ์สิ้นสุด/ร่างเก่า/จัดการไปแล้ว/ปิดใช้) แสดงข้อความภาษาคน |
| admin ของ อปท. / superadmin | กล่อง "ตั้งค่าผู้มีสิทธิ์ยืนยันประกาศ" (พับไว้ ไม่โหลดรายชื่อจนกว่าจะเปิด): ตั้ง/ถอน/บันทึกข้อความอ้างอิง · ครบ 5 คนปิดปุ่มตั้ง · เตือนเมื่อยังไม่มีผู้ยืนยัน |

- ช่องกรอกในส่วนนี้มีช่องเดียว (อ้างอิงอำนาจ ของ admin) · ปุ่มทุกปุ่มติดป้าย `data-wa-action` · ข้อความประกาศแสดงตามที่ระบบร่างทุกตัวอักษร แก้ไม่ได้ (ฐานข้อมูลล็อกด้วย)
- ส่วนเหตุการณ์ (`data-we-list`) ยังอ่านอย่างเดียวเหมือนเดิม — เทสต์เดิมของ PR 3.2 ยังล็อกไว้ (ตรวจแยกจากส่วนประกาศ)

**เจ้าหน้าที่ — หน้าแรก "ต้องทำตอนนี้"** แถว "ประกาศน้ำ-ฝนรอคุณยืนยัน" (`StaffOperationalDashboard.jsx`) ขึ้นเฉพาะผู้ยืนยันที่มีร่างที่ยืนยันได้จริง — ร่างหมดความหมายใน 3 ชม. ถ้าผู้มีสิทธิ์ไม่เห็นก็ไม่มีประกาศ · ถามผ่าน `water_announcement_todo` (ฮุก `useHomeRpc` แคช 30 วิ ไม่ poll · ทำรายการแล้วล้างแคช) · โหลดพลาด = ไม่มีแถว ไม่กระทบ "ไม่มีงานค้าง" ของงานอื่น · ไม่ใช่ผู้ยืนยัน = ไม่มีแถวและไม่เพิ่มกล่องให้

**ประชาชน** (`WaterAnnouncementCard.jsx` + `useWaterAnnouncement.js`)
- หน้าแรก (แก้ `WaterAlertBanner.jsx` ไฟล์เดียว ใช้ได้ทั้ง 3 ธีม): มีประกาศ = **ขึ้นประกาศแทนแถบแจ้งเตือนดิบ** (ไม่ซ้อนสองแถบ) ครบอายุ/ยกเลิก = แถบดิบกลับมา
- หน้า /water-situation: การ์ดอยู่บนสุดของเนื้อหา แถบแจ้งเตือนดิบของหน้าอยู่ตามเดิม (หน้านี้คือหน้าข้อมูลละเอียด)
- ข้อความตามที่ผู้มีสิทธิ์ยืนยันทุกตัวอักษร + เวลาเผยแพร่/ใช้ได้ถึง/เหลืออีก + "ผ่านการยืนยันจากเจ้าหน้าที่ที่หน่วยงานกำหนดแล้ว" (ไม่แสดงชื่อผู้ยืนยัน) · ไม่มีปุ่ม/ช่องกรอก
- ถามฐานข้อมูลตอนเปิดหน้า + ทุก 5 นาทีตอนแท็บแสดงอยู่ (เท่าแถบเดิม) — ไม่มีประกาศได้ `null` ก้อนเล็กมาก · โหลดพลาด = คงค่าเดิม ไม่แสดง error บนหน้าแรก

## ตาราง และบันทึกย้อนตรวจ

- ข้อความ/ที่มา/เวลาร่าง/หน่วยงานของประกาศ **แก้ไม่ได้** · ลบแถว/ล้างตารางไม่ได้ (trigger ล็อก แม้เป็นเจ้าของฐานข้อมูล) · ฉบับที่ปิดแล้วฟื้นไม่ได้ · สถานะเปลี่ยนตามเส้นทางที่กำหนดเท่านั้น · ลบ อปท. ทั้งก้อน (FK cascade) ยังทำได้
- ข้อความที่ผู้มีสิทธิ์ยืนยัน = ข้อความที่ระบบร่าง (ตรวจย้อนได้ว่าประกาศอะไร ตามค่าอะไร)
- ทุกการตัดสินของคน (ยืนยัน/ไม่ประกาศ/ยกเลิก) และการตั้ง/ถอนผู้ยืนยัน เขียนลง `audit_logs` เดิมฝั่งเซิร์ฟเวอร์ (หน้าจอข้ามไม่ได้) — `approve` / `reject` / `cancel` / `update` · metadata ไม่มีข้อมูลบุคคลอื่น
- ตารางทั้ง 3 (`water_announcement_settings` · `water_announcements` · `water_announcement_approvers`) ปิดสนิท (RLS เปิด ไม่มี policy ถอนสิทธิ์ anon/authenticated ทั้งหมด) อ่าน/เขียนผ่านฟังก์ชัน SECURITY DEFINER เท่านั้น · ไม่เก็บชื่อ เบอร์ พิกัดของบุคคล

## วิธีเปิด/ปิด (เจ้าของระบบ — ฝั่ง SQL editor)

```sql
-- เปิดบน demo (สนามซ้อม) เพื่อทดสอบ
INSERT INTO public.water_announcement_settings (municipality_id, enabled)
SELECT id, true FROM public.municipalities WHERE slug = 'demo'
ON CONFLICT (municipality_id) DO UPDATE SET enabled = true, updated_at = now();

-- ปิดทันที (หน้าประชาชนหยุดแสดงฉบับที่ค้างอยู่ด้วย)
UPDATE public.water_announcement_settings SET enabled = false, updated_at = now() WHERE municipality_id = '<id>';

-- หยุดร่างทั้งระบบ
SELECT cron.unschedule('water-announce-tick-hourly');
```
