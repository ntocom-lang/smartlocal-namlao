# ADAPTERS.md — Adapter รายเครื่องมือ (ต้นฉบับ)

`docs/ai/CORE.md` + `DOMAIN.md` + `SAFETY.md` คือกฎที่ AI ทุกตัวต้องยึดเหมือนกัน
ไฟล์นี้เก็บ **ส่วนต่างเฉพาะเครื่องมือ** — พฤติกรรมที่ต่างกันเพราะตัวเครื่องมือเอง
ไม่ใช่เพราะเนื้องานต่างกัน

ทำไม Codex ต้องมาอยู่ไฟล์นี้ แต่ Claude/Gemini ไม่ต้อง:
- Claude Code อ่าน `CLAUDE.md` (root) / Antigravity อ่าน `GEMINI.md` (root)
  → 2 ไฟล์นั้นเขียนมือได้ตามปกติ `ai-sync.mjs` ไม่แตะ
- **Codex ไม่อ่านไฟล์ชื่อ `CODEX.md`** — อ่าน `AGENTS.md` ของรีโป (ซึ่งเป็นไฟล์ generated
  และ AI ตัวอื่นก็อ่านด้วย) กับ `~/.codex/AGENTS.md` ที่เป็น global
  ⇒ adapter ของ Codex ยัดลง `AGENTS.md` ไม่ได้ (จะไปกวน AI ตัวอื่น) ต้องไปออกที่ global
  ⇒ global ไม่อยู่ใน git ⇒ ต้องมีต้นฉบับในรีโปให้ `ai-sync.mjs` generate ไม่งั้นเครื่องใหม่ไม่มีเลย

ทำไม Claude มี adapter "เลือกรุ่นและ effort" ที่นี่ด้วย (เจ้าของระบบสั่ง 2026-11-08):
- ชื่อรุ่น/effort/subagent เป็นของ Claude Code เท่านั้น ใส่ใน `CORE.md` ไม่ได้ เพราะ `CORE.md` ไปถึง Gemini/Codex ด้วย
- ต้องใช้ทุกโปรเจกต์และทุก IDE (VS Code + Antigravity ใช้ `~/.claude` ชุดเดียวกัน)
  ⇒ ออกที่ `~/.claude/CLAUDE.md` (global) ไม่ใช่ `CLAUDE.md` ของรีโป
- ค่าตั้งคู่กันอยู่ที่ `docs/ai/claude/` — `settings.json` (รุ่น/effort เริ่มต้น) + `agents/*.md` (subagent)
  `npm run ai:sync` เอาไปลง `~/.claude/` ให้ทุกเครื่อง (PC + โน้ตบุค) ไม่ต้องตั้งมือ
- ⚠️ `effortLevel` ชั้นบนสุด**ไม่มีผลกับ Opus 5.5** (เอกสาร Claude Code model-config) — effort ของรุ่นนั้น
  อ่านจาก `modelSettings["claude-opus-5-5"].effortLevel` เท่านั้น ⇒ `settings.json` ต้นฉบับจึงมี `modelSettings` ด้วย
  (ตรวจพบ 2026-11-12: PC ได้ high เพราะเคยกด `/effort` ไว้ เครื่องที่ตั้งจาก `ai:sync` อย่างเดียวจะได้ค่าเริ่มต้นของรุ่นแทน)

ทำไม Antigravity มี adapter "แนะนำรุ่น" ที่นี่ (เจ้าของระบบสั่ง 2026-11-12):
- agent ของ Antigravity เองเลือกรุ่นจาก dropdown ใต้ช่องพิมพ์เท่านั้น สลับรุ่นตัวเองไม่ได้ ไม่มี subagent/effort แบบ Claude Code
  ⇒ ทำอัตโนมัติได้แค่ "แนะนำบรรทัดแรก" ให้ผู้ใช้กดเลือกเอง
- agent ของ Antigravity อ่าน `~/.gemini/GEMINI.md` (global) ⇒ adapter นี้ออกที่ไฟล์นั้นที่เดียว
  ส่วน extension Claude Code ที่ติดตั้งใน Antigravity อ่าน `~/.claude/CLAUDE.md` ได้ adapter Claude ไปแล้ว ไม่ต้องได้ตัวนี้
- ไม่ระบุชื่อรุ่น เพราะรายชื่อใน dropdown เปลี่ยนบ่อย ให้ agent จับคู่ "ระดับงาน" กับตัวเลือกที่เห็นขณะนั้น

[Adapter — Claude: เลือกรุ่นและ effort]
- ทุก session เริ่มที่ Opus + effort high (ค่าจาก `docs/ai/claude/settings.json`)
  max เปิดให้ใช้ได้เมื่อจำเป็น แต่ตั้งเป็นค่าเริ่มต้นไม่ได้ (Claude Code เก็บ max ถาวรไม่ได้ ใช้ได้ทีละ session)
  session หลักเปลี่ยนรุ่น/effort ของตัวเองไม่ได้ ⇒ เลือกรุ่นต่องานด้วยการส่งให้ subagent ตามตารางนี้
  ผู้ใช้อนุญาตถาวรให้ส่งต่อตามตารางนี้โดยไม่ต้องถามก่อน
- ออกแบบระบบ ตรวจระเบียบ ฐานข้อมูล/RLS/สิทธิ์ บั๊กยาก → ทำเองใน session หลัก (Opus + high)
- migration ที่จะรันบนฐานจริง / แก้ RLS / GRANT / SECURITY DEFINER → เขียนเอง แล้วส่ง
  `migration-reviewer` (Opus + xhigh) ตรวจทุกครั้งก่อนเสนอให้รัน แจ้งผลตรวจพร้อมไฟล์
- เขียนโค้ดตามแผนที่ผู้ใช้อนุมัติแล้ว แตะตั้งแต่ 3 ไฟล์ หรืองานยาว (หน้าจอ ใบพิมพ์ เทสต์)
  → `implementer` (Sonnet + high) ส่งแผนที่อนุมัติ + path worktree ให้ครบ แล้วตรวจ diff เองก่อนรายงาน
- ค้นกว้างหลายโฟลเดอร์ ไล่หาว่าอะไรเรียกอะไร → `scout` (Sonnet + medium)
- แก้จุดเล็ก ถามสั้น ค้น 1–2 ไฟล์ → ทำเองทันที ไม่ส่งต่อ
  (subagent เริ่มจากศูนย์ต้องอ่านไฟล์ใหม่หมด งานเล็กส่งต่อแพงกว่าทำเอง)
- max ใช้เฉพาะเมื่อความถูกต้องสำคัญกว่าโทเคนจริงๆ — ห้ามใช้เป็นค่าประจำ ถ้าผู้ใช้สลับเองด้วย `/model` หรือ `/effort` ค่าที่ผู้ใช้เลือกชนะเสมอ
- เทิร์นที่ส่งต่องาน ให้บอกในบรรทัดแรกว่า "ใช้: <agent> (<รุ่น> + <effort>)"

งานที่สลับเองไม่ได้ ให้แนะนำผู้ใช้เอง ไม่ต้องรอถาม (เจ้าของระบบสั่ง 2026-11-08)
- รุ่น/effort ของ session หลักไม่เหมาะกับงาน ให้แนะนำเมื่อเจอกรณีต่อไปนี้
  · งานออกแบบ ตรวจระเบียบ ฐานข้อมูล/RLS/สิทธิ์ บั๊กยาก แต่ session ไม่ใช่ Opus หรือ effort ต่ำกว่า high
    → แนะนำ Opus 5.5 + high
  · migration ที่จะรันบนฐานจริง หรือบั๊กที่แก้ 2 รอบแล้วยังไม่ออก → แนะนำ Opus 5.5 + xhigh
  · แนะนำ Opus 5.5 + max เฉพาะ: บั๊กที่ xhigh แล้วยังไม่ออก, เหตุด้านความปลอดภัย/ข้อมูลรั่ว,
    migration ที่ลบหรือแปลงข้อมูลจริงแบบย้อนไม่ได้, งานที่ผลผิดแล้วกระทบสิทธิประชาชน/ระเบียบ
    และบอกด้วยว่างานจบแล้วให้เปิดแชตใหม่ (max หายเองเมื่อขึ้น session ใหม่ กลับเป็น high)
  · งานเล็ก/ถามสั้นต่อกันยาว หรืองานเสี่ยงจบแล้ว แต่ session ยังตั้ง xhigh/max ไว้ → แนะนำลดเป็น high หรือ medium
- แชตยาวกินโทเคนมากกว่าการเลือกรุ่น (ทุกข้อความส่งประวัติทั้งหมดซ้ำ) ให้แนะนำเปิดแชตใหม่เมื่อ
  · ผู้ใช้เริ่มงานใหม่ที่ไม่ต่อจากงานเดิม (ราว 1 งาน/1 PR ต่อแชต)
  · แชตถูกย่อ (compact/summary) มาแล้ว หรือทำไปหลายงานในแชตเดียว
  · งานเดิมจบแล้ว (PR merge / ส่งมอบแล้ว)
- รูปแบบ: บรรทัดแรกของคำตอบ บรรทัดเดียว เช่น
  "💡 แนะนำ: เปิดแชตใหม่ แล้วสลับเป็น Opus 5.5 + xhigh (`/model opus` → `/effort xhigh`) — งานนี้เป็น migration ที่จะรันฐานจริง และแชตนี้ยาวแล้ว ประหยัดโทเคนกว่าทำต่อที่นี่"
  ถ้าแนะนำแชตใหม่ ให้ปิดท้ายด้วยข้อความเริ่มแชตใหม่ 1–3 บรรทัดที่ผู้ใช้วางได้ทันที
  (งานอะไร สาขา/worktree/PR ไหน ทำถึงไหน) และบันทึกสิ่งที่ต้องรู้ลงความจำก่อน
- งานเสี่ยงสูง (migration รันฐานจริง, แก้ RLS/GRANT) ใน session ที่รุ่นต่ำกว่าที่แนะนำ → แนะนำแล้วรอผู้ใช้ตอบก่อนลงมือ
  งานอื่น → แนะนำบรรทัดเดียวแล้วทำต่อได้เลย
- แนะนำเรื่องเดียวกันครั้งเดียวต่องาน ผู้ใช้ไม่สลับก็ทำต่อตามที่สั่ง ห้ามเตือนซ้ำทุกข้อความ
- ไม่รู้ effort ปัจจุบันของ session ให้แนะนำเฉพาะรุ่น/แชตใหม่ ห้ามเดาว่า session ตั้ง effort อะไร

[Adapter — Antigravity: แนะนำรุ่นของ agent]
- ใน Antigravity ผู้ใช้เป็นคนเลือกรุ่นจาก dropdown ใต้ช่องพิมพ์ agent สลับรุ่นของตัวเองไม่ได้
  ⇒ หน้าที่ของ agent คือแนะนำให้ถูกจังหวะ ไม่ต้องรอผู้ใช้ถาม (เจ้าของระบบสั่ง 2026-11-12)
- แบ่งงานเป็น 2 ระดับ แล้วจับคู่กับตัวเลือกที่มีใน dropdown ขณะนั้น ห้ามอ้างชื่อรุ่นจากความจำ
  · งานคิดลึก — ออกแบบระบบ ตรวจระเบียบ ฐานข้อมูล/RLS/สิทธิ์ migration บั๊กยาก
    งานที่ผิดแล้วกระทบเงิน สิทธิประชาชน หรือระเบียบ
    → รุ่นที่เก่งที่สุด หรือโหมดคิดลึก (thinking/high) ที่มีให้เลือก
  · งานเร็ว — แก้จุดเล็ก ถามสั้น ค้นไฟล์ เขียนโค้ดตามแผนที่ผู้ใช้อนุมัติแล้ว
    → รุ่นเร็ว/เบา (fast/low) ประหยัดโควตา
- แนะนำเฉพาะเมื่อระดับงานไม่ตรงกับรุ่นที่ใช้อยู่ ถ้าไม่รู้ว่ากำลังใช้รุ่นไหน
  ให้แนะนำเฉพาะงานคิดลึก ห้ามเดาว่ากำลังใช้รุ่นอะไร
- รูปแบบ: บรรทัดแรกของคำตอบ บรรทัดเดียว เช่น
  "💡 แนะนำ: เลือกรุ่นที่เก่งที่สุด/โหมดคิดลึกใน dropdown — งานนี้เป็น migration ที่จะรันฐานจริง"
- งานเสี่ยงสูง (migration รันฐานจริง แก้ RLS/GRANT ลบหรือแปลงข้อมูลจริง) แนะนำแล้วรอผู้ใช้ตอบก่อนลงมือ
  งานอื่นแนะนำบรรทัดเดียวแล้วทำต่อได้เลย
- แนะนำเรื่องเดียวกันครั้งเดียวต่องาน ผู้ใช้ไม่สลับก็ทำต่อตามที่สั่ง ห้ามเตือนซ้ำทุกข้อความ
- แชตยาวกินโควตามากกว่าการเลือกรุ่น (ทุกข้อความส่งประวัติทั้งหมดซ้ำ) ให้แนะนำเปิดแชตใหม่เมื่อ
  เริ่มงานใหม่ที่ไม่ต่อจากงานเดิม หรืองานเดิมจบแล้ว พร้อมข้อความเริ่มแชตใหม่ที่วางได้ทันที
- โควตาฟรีหมด ให้บอกผู้ใช้ตรงๆ ห้ามแนะนำแพ็กเกจเสียเงิน ($0 Budget Policy)

[Adapter — Codex]
- เปิดรีโปไหน ให้อ่าน `AGENTS.md` ของรีโปนั้นทั้งฉบับก่อนลงมือ
  ถ้าข้อไหนขัดกับไฟล์นี้ ให้ยึด `AGENTS.md` ของรีโปเป็นใหญ่
- ตอบไม่เกิน 400 คำ เว้นแต่ผมขอโค้ดหรือเอกสารเต็ม
  ห้ามขึ้นต้นด้วยคำเกริ่นหรือคำชม ห้ามย่อหน้าสรุปซ้ำท้ายคำตอบ
- ก่อนแก้ไฟล์เกิน 3 ไฟล์ ให้สรุปแผนก่อน (ไฟล์ไหน แก้อะไร ทำไม) แล้วรอ approve
  คำว่า "ทำได้เลย" คือ approve ของงานชิ้นนั้นชิ้นเดียว ไม่ใช่ blanket approval ของงานถัดไป
- เรื่อง commit/push — `SAFETY.md` ห้าม commit/push เองโดยไม่ถาม ข้อนั้นยังบังคับอยู่
  ยกเว้นโหมด cloud ที่ต้องส่งงานผ่านสาขาของตัวเองเท่านั้น กรณีนั้น:
  push ได้เฉพาะสาขา `codex/<ชื่องาน>` ที่ตัดจาก `origin/master`
  ห้าม push เข้า master ห้าม force push ห้าม merge PR เอง — ให้ผมเป็นคนกด merge
- ห้าม auto-approve คำสั่งทำลายด้วยตัวเอง แม้อยู่ในโหมดที่อนุญาตให้ทำได้
  (`rm -rf`, `git reset --hard`, force push, แก้ `.env`/secret/CI config) — หยุดแล้วถามก่อนทุกครั้ง
- $0 Budget Policy บังคับกับตัวเองด้วย: ห้ามเสนอทางออกเป็น paid plan หรือสลับไปเรียก
  API ที่คิดเงินต่อ token เมื่อโควตาฟรีหมด ให้หยุดแล้วบอกผมว่าหมดแล้ว
- ถ้าผมพิมพ์ "RECHECK" ให้ไล่ทวนว่าคำตอบหรือ diff ในเทิร์นก่อนหน้าละเมิดข้อไหนของ
  `AGENTS.md` บ้าง (ถ้าไม่ละเมิดให้บอกตรงๆ ว่าไม่ละเมิด)
