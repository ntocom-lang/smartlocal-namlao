# แคชค่าน้ำในเครื่องผู้ชม + ปุ่มเรดาร์ฝน (หน้า /water-situation)

เพิ่ม 2569-10-28 หลังเจ้าของระบบสั่งเทียบหน้านี้กับเว็บเทศบาลตำบลหนองหอย (nh-water-monitor.web.app) แล้วหยิบเฉพาะสิ่งที่ตรงกับหลักของระบบเรา

## 1) แคชค่าล่าสุดในเครื่อง (`src/lib/waterCache.js`)

**แก้ปัญหาอะไร:** เปิดหน้านี้แล้วระบบดึงค่าน้ำไม่สำเร็จ (เน็ตสะดุด/ฐานข้อมูลตอบช้า) เดิมขึ้น "โหลดข้อมูลสถานการณ์น้ำไม่สำเร็จ" เป็นหน้าว่าง ทั้งที่เครื่องนี้เคยได้ค่ามาเมื่อไม่กี่ชั่วโมงก่อน

**กติกา (ห้ามเปลี่ยนโดยไม่ตั้งใจ — มีเทสต์คุม):**
- ใช้แคช **เฉพาะตอนดึงไม่สำเร็จ และยังไม่เคยได้ค่าจากระบบเลยในครั้งนั้น** — ห้ามเอาขึ้นจอระหว่างรอระบบตอบ (คนจะเห็นตัวเลขเก่าวาบก่อนค่าจริง เช่น ฝน 0 มม. ทั้งที่ตอนนี้ตก)
- เคยได้ค่าสดแล้ว รอบรีเฟรชถัดไปล้ม = คงค่าสดเดิมพร้อมข้อความเดิม "รอบล่าสุดโหลดไม่สำเร็จ" ไม่สลับไปใช้แคช
- ใช้ค่าจากแคชแล้ว **ต้องขึ้นป้ายเหลืองบนสุด** บอกว่าเป็นค่าที่เครื่องนี้เก็บไว้ พร้อมเวลาของข้อมูลเอง และมีปุ่ม "ลองใหม่"
- อายุนับจาก **เวลาของข้อมูล** (`synced_at` / `fetchedAt`) ไม่ใช่เวลาที่เครื่องบันทึก — เกิน **24 ชม.** ทิ้ง (ฝนสะสม 24 ชม. ที่เก่ากว่าหนึ่งวันไม่มีความหมาย) · 24 ชม. เป็นสมมติฐานของผม เปลี่ยนได้ที่ `WATER_CACHE_MAX_AGE_MS`
- แยกคีย์ตาม อปท. (`sl_water_situation_v1:<id>`) และตรวจ id ซ้ำในแถว · รายงานรายชั่วโมงแยกตามรหัสสถานี (`sl_water_hydro_v1:<รหัส>`)
- รายงานรายชั่วโมงที่ Worker ส่งมาเป็นค่าเก่าเพราะต้นทางล่ม (`refreshFailed`) **ไม่เขียนทับแคช** ไม่งั้นแคชถูกต่ออายุด้วยค่าเดิมซ้ำ
- ค่าจากแคชของรายงานรายชั่วโมงติด `failed: true` เสมอ → แผงขึ้น "ข้อมูลอาจไม่เป็นปัจจุบัน · ระดับน้ำล่าสุดที่ได้รับ" และไม่คำนวณเทียบชั่วโมงก่อน
- localStorage ใช้ไม่ได้/เต็ม/ข้อมูลเสีย/คนละเวอร์ชัน = ถือว่าไม่มีแคช หน้าทำงานเหมือนเดิม ไม่ error
- ข้อมูลที่เก็บเป็นค่าสาธารณะชุดเดียวกับที่หน้าแสดงอยู่แล้ว ไม่มีข้อมูลส่วนบุคคล · ไม่เพิ่มคำขอไปเซิร์ฟเวอร์ ไม่เพิ่มค่าใช้จ่าย

**ขอบเขต — แก้อะไรไม่ได้ (ตรวจบน production 2569-10-28):** ปิดเน็ตทั้งเครื่องแล้วเปิดหน้านี้ใหม่ เบราว์เซอร์ขึ้นหน้า "ไม่มีอินเทอร์เน็ต" ตั้งแต่ระดับ HTML เพราะ `src/sw.js` ไม่มี fallback ของหน้า และหน้าต้องดึงข้อมูลหน่วยงานก่อนถึงจะถึงขั้นค่าน้ำ แคชนี้จึงช่วยเฉพาะกรณี "หน้าเปิดได้ แต่ดึงค่าน้ำไม่สำเร็จ" · การทำให้เปิดแอปตอนออฟไลน์ได้จริงต้องแก้ service worker + เก็บข้อมูลหน่วยงาน ซึ่งกระทบทุกหน้าทุก อปท. และเคยมีปัญหาหน้าเว็บขาวหลัง deploy — แยกเป็นงานต่างหาก ต้องให้เจ้าของระบบตัดสินใจ

## 2) ปุ่ม "ดูเรดาร์ฝนล่าสุด"

- ลิงก์ออกหน้าทางการ 2 แห่ง เปิดแท็บใหม่ (`RADAR_LINKS` ใน `WaterSituationPage.jsx`): ThaiWater `/weather/radar` (ภาพเรดาร์ ดาวเทียม ข้อมูลกรมอุตุนิยมวิทยา) และ `weather.tmd.go.th` ของกรมอุตุนิยมวิทยา — ตรวจ 2569-10-28 ว่าเปิดได้และเป็นหน้าเรดาร์จริง
- **ไม่ฝังตัวเล่นของบุคคลที่สาม** (เว็บหนองหอยฝัง Windy) เพราะต้องโหลดสคริปต์ภายนอกและส่งข้อมูลผู้ชมออกนอกระบบ · เทสต์ห้าม `<iframe>`/`<script>`/`windy` ในหน้า
- เขียนกำกับใต้ปุ่มว่าไม่ใช่ประกาศเตือนภัยของ อปท. และไม่บอกเวลาที่น้ำจะมา
- ถ้าหน้าปลายทางย้ายหรือล่ม ต้องตรวจเองด้วยมือ: `www.tmd.go.th/radar` ตอบ 500 ตอนที่ตรวจ จึงไม่ใช้

## ที่ไม่ได้ทำจากการเทียบหนองหอย (ตั้งใจ)
- **พยากรณ์ระดับน้ำ +15 ชม.** — สมการฝึกกับสถานี P.1 ของเขาเท่านั้น ของเราไม่มีประวัติฝึก และ อปท. ออกตัวเลขพยากรณ์เองเสี่ยงถูกอ่านเป็นประกาศเตือนภัย (ต้องยืนยันกับระเบียบ/หน่วยงานเจ้าของอำนาจก่อน)
- **ป้ายสรุปเดียว "ปกติ/เฝ้าระวัง/วิกฤต"** และ **ฝนต้นน้ำจัดกลุ่มตามสถานีระดับน้ำ** — รอตัดสินใจ: ต้องให้ อบต. ยืนยันว่าสถานีฝนไหนอยู่ต้นน้ำของลำน้ำไหน ห้ามเดา
