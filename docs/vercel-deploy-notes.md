# หมายเหตุการ deploy บน Vercel

## ทำไม `vercel.json` ปิด deployment ของทุก branch

repo นี้ผูกกับ Vercel **4 โปรเจกต์** ที่ build จาก branch เดียวกัน

| โปรเจกต์ | ใช้ทำอะไร |
| --- | --- |
| `smartlocal-app` | เข้าผ่าน path (`/{slug}`) |
| `smartlocal-namlao` | เทศบาลตำบลน้ำเลา — ข้อมูลจริง |
| `smartlocal-tamnaktham` | เตรียมเสนอขายให้ อปท. — ต้อง deploy ได้ตลอด |
| `smartlocal-thungkaew` | เตรียมเสนอขายให้ อปท. — ต้อง deploy ได้ตลอด |

แปลว่า **push 1 ครั้ง = 4 deployment** และเปิด PR ก็ได้ preview อีก 4 วันที่ 28 ส.ค. 2569
พัฒนาระบบเข้าสู่ระบบด้วยรหัสจากมือถือ (PR #29–#33) จึงชนเพดาน deployment ต่อวันของแผน
Hobby จนคอมมิตที่ merge แล้ว (`d6c1c57`) ขึ้น production ไม่ได้ทั้ง 4 โปรเจกต์ —
เช็คทั้งหมดขึ้น `failure` พร้อมลิงก์ `upgradeToPro=build-rate-limit`
ซึ่งอัปเกรดไม่ได้เพราะโครงการนี้ถือนโยบายไม่มีค่าใช้จ่าย

ทางแก้ที่ใช้: ตัด preview ทิ้งทั้งหมด เหลือ build เฉพาะตอนเข้า `master`

```json
"git": {
  "deploymentEnabled": {
    "*": false,
    "**": false,
    "master": true
  }
}
```

ที่ต้องมีทั้ง `*` และ `**` เพราะ Vercel ใช้ minimatch ซึ่ง `*` ไม่ข้าม `/`
แต่ branch ที่นี่ตั้งชื่อแบบ `feat/...` `fix/...` จึงต้องพึ่ง `**`
ส่วน `master` ระบุ `true` ไว้ชัดเจน — เอกสาร Vercel กำหนดว่า branch ที่เข้าเงื่อนไข
หลายข้อ ถ้ามีข้อไหนเป็น `true` ก็ deploy ฉะนั้น **production ถูกบล็อกไม่ได้**
แม้ pattern ข้างบนจะเปลี่ยนความหมายไป

ผลข้างเคียงที่ต้องรับ: **ไม่มี preview URL ให้ทดสอบก่อน merge อีกแล้ว**
ถ้างานไหนต้องการ preview จริงๆ ให้ลบสองบรรทัด `"*"` กับ `"**"` ออกชั่วคราว
แล้วใส่กลับหลัง merge

## ยังต้องไปทำที่ Vercel dashboard (แก้จาก repo ไม่ได้)

`vercel.json` ไฟล์เดียวถูกอ่านโดยทั้ง 4 โปรเจกต์ จึงตั้งค่าแยกรายโปรเจกต์ไม่ได้

**ปลุก `d6c1c57` ให้ขึ้น production** — เมื่อโควตารีเซ็ตแล้ว เข้าแต่ละโปรเจกต์
→ Deployments → เลือกคอมมิตล่าสุด → Redeploy (ทำทีละโปรเจกต์ทั้ง 4)
หรือ push คอมมิตใหม่เข้า `master` ก็ได้ผลเดียวกัน

ที่เคยคิดว่าจะตัด `tamnaktham` / `thungkaew` ออกจาก auto-deploy **ทำไม่ได้** —
ทั้งสองตัวกำลังจะเสนอขายให้ อปท. จึงต้องอยู่ในสภาพสาธิตได้ตลอด ไม่ใช่ของทิ้งขว้าง

## ⚠️ ข้อจำกัดที่ค้างคอ ต้องตัดสินใจก่อนขายจริง

### 1. แผน Hobby ห้ามใช้เชิงพาณิชย์

เอกสาร Vercel ระบุตรงๆ ว่า

> As stated in the fair use guidelines, the Hobby plan restricts users to
> non-commercial, personal use only.
> — <https://vercel.com/docs/plans/hobby>

ถ้าขายระบบนี้ให้ อปท. แล้วยัง host บน Hobby = ใช้เชิงพาณิชย์บนแผนที่ห้ามไว้
Vercel มีสิทธิ์ระงับบัญชี ซึ่งจะทำให้ **บริการของ อปท. ที่เป็นลูกค้าจริงดับพร้อมกันทั้งหมด
โดยไม่มีสัญญาณเตือน** สำหรับระบบราชการที่ประชาชนใช้ยื่นเรื่อง นี่คือความเสี่ยงระดับที่รับไม่ได้

แผน Pro ราคา 20 USD ต่อผู้ใช้ต่อเดือน ซึ่งขัดนโยบายไม่มีค่าใช้จ่ายของโครงการ
จึงต้องเลือกทางใดทางหนึ่งก่อนส่งมอบให้ลูกค้ารายแรก:

- ย้ายไป host ที่ free tier อนุญาตให้ใช้เชิงพาณิชย์ (ต้องพอร์ต `/api/ssr`
  ที่ตอนนี้เป็น Vercel Function)
- ให้ อปท. แต่ละแห่งเป็นผู้ถือบัญชี host และออกค่าใช้จ่ายเอง — ต้นทุนไปอยู่ฝั่งลูกค้า
  ซึ่งตรงกับรูปแบบการจัดซื้อของราชการอยู่แล้ว และแยกความเสี่ยงออกจากกันด้วย
- ยอมจ่าย Pro เอง แล้วบวกกลับเข้าไปในราคาขาย

**ยังไม่ได้ตัดสินใจ** — ห้ามส่งมอบให้ อปท. รายแรกก่อนเคลียร์ข้อนี้

### 2. โควตา build ไม่ scale ตามจำนวนลูกค้า

Hobby ให้ **100 deployment ต่อวัน** และทุกโปรเจกต์ build จาก push เดียวกัน
ฉะนั้นจำนวนครั้งที่ push ได้ต่อวัน = 100 ÷ จำนวน อปท.

| จำนวน อปท. | push ได้ต่อวัน |
| --- | --- |
| 4 (ตอนนี้) | 25 |
| 10 | 10 |
| 20 | 5 |

ขายได้มากขึ้น = แก้โค้ดได้น้อยลง ซึ่งกลับหัวกลับหาง Pro ให้ 6,000 ต่อวันก็จริง
แต่ติดข้อ 1 อยู่ดี

ทางแก้เชิงสถาปัตยกรรม: รวมเหลือ **โปรเจกต์เดียว** แล้วผูกหลาย custom domain
— `detectTenantSlug()` ใน [`src/contexts/TenantContext.jsx`](../src/contexts/TenantContext.jsx)
แยก tenant จาก hostname อยู่แล้ว (และ `computeBasename()` ใน
[`src/lib/basename.js`](../src/lib/basename.js) เช็คแพทเทิร์นเดียวกัน ต้องแก้คู่กันเสมอ)
ได้ 1 build ต่อ push ไม่ว่าจะมีลูกค้ากี่ราย แต่ต้องเลิกพึ่งชื่อ
`smartlocal-{slug}.vercel.app` (subdomain ผูกกับชื่อโปรเจกต์) จึงต้องรอให้ อปท.
มีโดเมนของตัวเอง หรือหันไปใช้โหมด path (`/{slug}`) ที่แอปรองรับอยู่แล้ว
