# พยากรณ์อากาศในพื้นที่ — กรมอุตุนิยมวิทยา (NWP)

การ์ด "คาดหมายสภาวะอากาศ 7 วันข้างหน้า" (ตาราง 7 วันแบบภาพคาดหมายของกรม ปรับให้ชาวบ้านอ่านง่าย) บนหน้า `/water-situation` ของทุก อปท. (ประชาชนเห็นได้ ไม่ต้องล็อกอิน)
เจ้าของระบบสั่ง 2569-11-15: เห็นได้ทุกคน **แต่ต้องอ้างอิงแหล่งข้อมูลด้วย** — การ์ดแสดงที่มาเสมอ (ชื่อกรม + ลิงก์เอกสาร + เวลาที่ดึง + จุดกริด)

## ที่มา / ค่าใช้จ่าย
- NWP API ของกรมอุตุนิยมวิทยา https://data.tmd.go.th/nwpapi/doc/ — ฟรี เอกสารบริการของกรมระบุ "ไม่มีค่าธรรมเนียมและค่าบริการ" (ตรวจ 2569-11-15) ⇒ ตรงนโยบาย $0
- โควตาของกรม: 60 คำขอ/นาที · 100,000 datapoint/ชม. (เกินได้ 429) — ภาระจริง 4 อปท. ≈ 660 datapoint/รอบ (รายละเอียดหัวไฟล์ cron)
- ทดสอบยิงจาก IP ของ Supabase แล้ว 2569-11-15: ตอบ 200 (ต่างจาก ews / ศูนย์น้ำแพร่ ที่บล็อก IP ต่างประเทศ)

## ลำดับ apply / deploy (ห้ามสลับ — cron ที่ยิงก่อนฟังก์ชันพร้อมจะพังเงียบทุกรอบ)
1. apply `20261126100000_tmd_forecast_table.sql` (ตาราง)
2. apply `20261126100100_tmd_forecast_rpc.sql` (RPC)
3. deploy `npx --no-install supabase functions deploy tmd-sync --no-verify-jwt --project-ref <ref>` (`--no-verify-jwt` จำเป็น: pg_cron ไม่มี JWT) และตรวจว่า secret ทั้ง 3 ตัวตั้งแล้ว
4. apply `20261126100200_tmd_forecast_cron.sql` (cron) — ⚠️ หลังจากนี้ Telegram ของ อปท. ที่ตั้ง `telegram_group_id` + เปิดโมดูล `water-situation` เริ่มได้ข้อความจริง
5. ตรวจ: ยิง `{"test": true}` ได้ แล้วเปิด `/water-situation` ของ demo ดูว่าการ์ดขึ้น · หลังรอบ cron จริงรอบแรก `job_heartbeats` ต้องมีแถว `tmd-sync` (โหมดทดสอบไม่ลงสมุด)
6. deploy `thaiwater-watchdog` ใหม่จาก master หลัง merge (`--no-verify-jwt` เหมือนเดิม) — เพิ่ม `tmd-sync` ใน `WATCHED_JOBS` (ค้างเกิน 375 นาที = พลาด 2 รอบติด → แจ้งกลุ่มผู้ดูแลระบบ พร้อม last_error เช่น token หมดอายุ)
(CI ไม่ deploy Edge Function ให้ — ต้อง deploy เอง ดู `docs/ai/NOTES.md`)

ย้อนกลับ: `SELECT cron.unschedule('tmd-sync-3h');` แล้ว (ถ้าต้องการ) drop RPC/ตาราง — ข้อมูลเป็นแค่สำเนาพยากรณ์ ดึงใหม่ได้ภายใน 3 ชม.
ก่อน apply ไฟล์ 1–2 หน้าเว็บไม่พัง: RPC ยังไม่มี = error → การ์ดไม่แสดง

## กติกาแจ้งเตือน Telegram (อ่านจากหัว `tmd-sync/index.ts`)
- พยากรณ์รายวัน วันนี้ถึง 2 วันข้างหน้า (รวม 3 วัน) มีวันที่ฝนรวม 24 ชม. ถึง "ฝนหนัก" ≥ 35.1 มม. (เกณฑ์กรมอุตุฯ ชุดเดียวกับ `RAIN_LEVELS` ใน `src/lib/waterSituation.js`)
- ส่งครั้งเดียวต่อ "วันที่ถูกพยากรณ์ × ระดับ" (ฝนหนัก / ฝนหนักมาก ≥ 90.1) — ตัวเลขขยับไม่ส่งซ้ำ · ยกระดับเป็นฝนหนักมากได้ข้อความใหม่ · พยากรณ์ลดลงไม่ส่ง "ยกเลิก"
- ข้อความบอกเสมอว่าเป็นผลพยากรณ์จากแบบจำลอง อาจคลาดเคลื่อน ไม่ใช่ประกาศเตือนภัยของกรมหรือ อปท. (ไม่สั่งการ ไม่ประกาศแทนผู้บริหาร)
- เทสต์ `test:tmd-forecast` อ่านค่า `HEAVY_RAIN_MM` / `VERY_HEAVY_RAIN_MM` ในฟังก์ชันมาเทียบกับ `RAIN_LEVELS` — แก้เกณฑ์ฝั่งใดฝั่งหนึ่งต้องแก้ทั้งคู่

## พฤติกรรมของการ์ด (ที่ตัดสินใจไว้)
- ไม่มีข้อมูล / RPC ผิดพลาด / อปท. ปิด = **ไม่แสดงการ์ด** (ส่วนเสริม ไม่ขึ้น error) · รอบโหลดพลาดแต่เคยได้ของ อปท. เดิม = คงของเดิม
- ค่า `null` = "–" ไม่เคยแปลงเป็น 0 (null = กรมไม่ส่งค่า ≠ ไม่มีฝน) · รายชั่วโมงที่ไม่มีค่าวาดเป็นเส้นประ
- ป้ายระดับฝน (ไม่มีฝน/เล็กน้อย/ปานกลาง/หนัก/หนักมาก) ใช้ `rainLevel` เดิม **กับฝนรายวัน 24 ชม. เท่านั้น** — ฝนรายชั่วโมงไม่ติดป้าย เพราะเกณฑ์เป็นของช่วง 24 ชม.
- **หน้าตา (รอบ 2 ตามภาพคาดหมาย 7 วันของกรม · เจ้าของสั่ง 2569-11-15):** แถบหัว (ตรา/ชื่อ อปท. + "คาดหมายสภาวะอากาศ 7 วันข้างหน้า" + ช่วงวันที่ พ.ศ. + แคปซูล "มุ่งสู่เมืองอัจฉริยะ (Smart City)") → ตาราง คอลัมน์ = 1 วัน (หัว "วันนี้" / "พรุ่งนี้" / "วันจันทร์" … + วันที่สั้น) แถว สภาพอากาศ / อุณหภูมิสูงสุด (แดง) / ต่ำสุด (ฟ้า) / ลม / ฝน → แถบคำอธิบายระดับฝนและลม → ส่วนพับ "ดูฝนรายชั่วโมง" → แถบท้าย (ที่มา + ลิงก์ + คำ "Smart City Local") → เวลาที่ดึง / จุดกริด / คำกำกับ
- แถวฝน = คำง่าย (ไม่มีฝน / ฝนเล็กน้อย / ฝนปานกลาง / ฝนหนัก / ฝนหนักมาก จาก `RAIN_LEVELS`) + ตัวเลข มม. ตัวเล็ก · **ไม่มี "โอกาสเกิดฝน %"** เพราะเราไม่มีข้อมูลนี้ (ห้ามเดา — เทสต์กันไว้)
- แถวลมใช้ `ws10m` (ลมสูงสุดของวัน m/s → km/h ×3.6 ปัดจำนวนเต็ม) + `wd10m` (ทิศที่ลม "พัดมาจาก") · ลูกศรชี้ไปทางที่ลมพัดไป (wd10m + 180°) · ข้อความ "จาก<ทิศ>" 8 ทิศภาษาไทย · ไม่มีทิศ = ไม่วาดลูกศร (ไม่เดาเป็นเหนือ)
  ระดับลม (ลมเบา 0–5 · อ่อน 5–10 · เอื่อย 10–20 · ปานกลาง 20–30 · แรง >30 กม./ชม.) และสี **คัดจากภาพแถบสัญลักษณ์ของกรม ยังไม่ได้เทียบเอกสาร/ตัวบท** · ขอบบนนับรวม (ภาพกรมลงสีเขียวให้ 10 กม./ชม. เหลืองให้ 11)
- มือถือ: ตารางกว้างขั้นต่ำ 44rem เลื่อนแนวนอนในกรอบตาราง (คอลัมน์ชื่อแถวปักซ้าย · คำบอก "เลื่อนดูวันถัดไป →" ขึ้นเฉพาะตอนล้นกรอบจริงและหายเมื่อเลื่อนสุด) หน้าทั้งหน้าไม่ล้น · ตัวอักษรไม่ต่ำกว่า 12px · แท็บเล็ตที่มีเมนูข้างกินที่ (กรอบการ์ด ~480px) ก็เลื่อนด้วย เห็นครบ 7 วันโดยไม่เลื่อนเมื่อกรอบกว้าง ≥ ~704px
- ห้ามใช้โลโก้กรมอุตุฯ / Digital Platform ในการ์ด (เลียนแบบตราหน่วยงานอื่น) — ชื่อกรมเป็นข้อความที่มาเท่านั้น · รูปเดียวในการ์ดคือโลโก้ อปท. (`tenant.logo_url`) · เทสต์ตรวจ
- คำขวัญ Smart City ใช้ `POSTER_BADGE_TAG` ของภาพแชร์น้ำ-ฝน (import) · "Smart City Local" ประกาศใน `tmdForecast.js` (ภาพแชร์ไม่ได้ export เป็นค่า)
- ป้ายเหลือง "พยากรณ์ชุดนี้ดึงเมื่อ … อาจไม่เป็นปัจจุบัน" เมื่อชุดที่เก่าสุดดึงมาเกิน 12 ชม. (`TMD_STALE_HOURS`) หรือไม่รู้เวลาดึง
- ตัดช่วงที่ผ่านไปแล้วตามเวลาไทย: รายชั่วโมงตัดเมื่อชั่วโมงนั้นจบแล้ว (เก็บชั่วโมงปัจจุบัน) · รายวันตัดวันก่อนวันนี้
- สมมติฐาน: `time` รายชั่วโมงของกรมคือต้นชั่วโมงของค่านั้น (เอกสารไม่ได้ระบุชัด) — ถ้าจริงๆ เป็นยอดสะสมของชั่วโมงก่อนหน้า จะแสดงเลื่อนไป 1 ชั่วโมง ควรยืนยันกับเอกสารกรม
- ห้องผู้บริหาร: ลงทะเบียนเป็นแหล่งข้อมูล `src:tmd-forecast` (เฟส E2 แบบเดียวกับ `src:air`) ยังไม่มีตัวเลขบนหน้ารวม — ถ้าจะขึ้นการ์ดต้องมี rule + RPC แยก
