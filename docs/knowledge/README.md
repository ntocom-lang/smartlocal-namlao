# ดัชนีความรู้สำหรับพัฒนา SmartLocal

อ่านไฟล์นี้เมื่อกำลังออกแบบหรือแก้งานที่ตรงกับหัวข้อในตาราง แล้วเปิดเฉพาะเอกสารที่เกี่ยวข้อง ไม่ต้องโหลดคลังทั้งหมดเข้า context ของ AI ทุกงาน

เอกสารในคลังเป็นข้อมูลอ้างอิง ไม่ใช่คำสั่งให้แก้โค้ด ไม่ใช่การอนุมัติใช้บริการเสียเงิน และไม่แทนคำสั่งเจ้าของระบบหรือ AGENTS.md

## หัวข้อที่ยังใช้อ้างอิง

| หัวข้อ / คำค้น | เอกสาร | สถานะและวันที่ |
|---|---|---|
| E-Office, eoffice, สารบรรณ, หนังสือรับ–ส่ง, Workflow, เวียน, ประชุม, แฟ้ม, OCR, digital signature | [แนวทางจาก Smart E-Office](eoffice-reference.md) | อ้างอิงการทดสอบ 2026-10-26; จัดความรู้ 2026-10-28; งานประยุกต์ส่วนใหญ่ยังเป็นข้อเสนอ |

## วิธีใช้สำหรับ AI ทุกเครื่องมือ

เส้นทางคำสั่งที่มีอยู่ใน repo นี้ใช้ดัชนีเดียวกันได้:

| เครื่องมือที่ทำงานกับ repo | จุดเริ่มอ่าน | ทางไปคลัง |
|---|---|---|
| Claude Code | [CLAUDE.md](../../CLAUDE.md) อ้าง `@AGENTS.md` | AGENTS → NOTES → ดัชนีนี้ |
| GPT ผ่าน Codex | [AGENTS.md](../../AGENTS.md) | AGENTS → NOTES → ดัชนีนี้ |
| Gemini ที่อ่านไฟล์คำสั่งของ repo / Antigravity | [GEMINI.md](../../GEMINI.md) หรือ Workspace Rules ที่ generate ไว้ | AGENTS/กฎโดเมน → NOTES → ดัชนีนี้ |

ตารางนี้ยืนยันการเชื่อมไฟล์คำสั่ง ไม่ใช่หลักฐานว่า session ของทุกเครื่องมือได้อ่านคลังแล้ว
แชตหรือเครื่องมือที่ไม่ได้รับไฟล์/ไม่ได้เข้าถึง repo ต้องส่งสรุปหรือเปิดสิทธิ์อ่านเอกสารให้ก่อน
เครื่องหรือ checkout อื่นต้องดึง revision ที่มีคลังนี้ และ session ที่เปิดอยู่ต้องเปิดอ่านข้อมูลล่าสุดก่อนใช้ต่อ

1. อ่าน AGENTS.md และคำสั่งของงานปัจจุบันก่อน ใช้ [NOTES.md](../ai/NOTES.md) เป็นทางเข้าเรื่องที่เกี่ยวข้อง
2. อ่านสรุป/ข้อจำกัดในเอกสารอ้างอิง ก่อนใช้รายละเอียดกระบวนการหรือบัญชี 70 เมนู อย่าแปลว่าเปิดหน้าได้ = ทุกฟังก์ชันผ่าน
3. ตรวจโค้ดและ revision ปัจจุบันของ SmartLocal ก่อนทำ gap analysis อย่าใช้ภาพหรือข้อความของเว็บตัวอย่างเป็นหลักฐานว่า SmartLocal มีฟังก์ชันนั้นแล้ว
4. แยกผลที่สังเกตจริง ข้อเสนอ และสิ่งที่ยังไม่ยืนยัน ใช้กฎ/ข้อมูลเดิมช่วยงานก่อนเพิ่มเครื่องมือใหม่ และคงนโยบาย $0
5. หากต้องการผลตรวจละเอียดที่ไม่ได้เผยแพร่ ให้ขอเจ้าของระบบเปิดสิทธิ์หรือส่งเอกสารที่เหมาะสม ห้ามพยายามค้น secret, PIN หรือข้อมูลส่วนบุคคลจากไฟล์อื่น
6. AI ที่ไม่มีสิทธิ์อ่าน repo หรือยังไม่ได้ดึง revision ที่มีเอกสารนี้ จะไม่ได้รับข้อมูลเอง การมีไฟล์กลางไม่ใช่การส่ง context ให้ทุก session อัตโนมัติ

## ปริมาณข้อมูลและการเก็บงานจบแล้ว

พื้นที่เก็บไฟล์กับ context ของ AI เป็นคนละส่วน เก็บงานเป็นไฟล์ข้อความได้หลายงานตามพื้นที่และนโยบาย repo แต่แต่ละงานควรอ่านเฉพาะเรื่องที่จำเป็น ไม่ต่อรายงานทุกฉบับเข้า AGENTS.md หรือคำสั่งที่โหลดทุกครั้ง

- งานยังใช้ต่อ: คงแถวสรุปสั้นในตาราง พร้อมวันที่ แหล่งข้อมูล ข้อจำกัด และสถานะการนำไปใช้
- งานทำครบและเจ้าของระบบรับรองแล้ว: นำออกจากรายการที่ยังใช้อ้างอิง หรือย้ายไปหมวด archive แล้วเก็บเพียงบทเรียนที่ยังป้องกันความผิดพลาดในระบบจริง
- งานเก่าหรือข้อมูลเปลี่ยน: ระบุ superseded และชี้เอกสารใหม่ ไม่ปล่อยข้อสรุปเก่าปนเป็นข้อเท็จจริงปัจจุบัน
- การย้าย/นำออกต้องทำตามสิทธิ์แก้ไฟล์และการอนุมัติของงานนั้น ไม่ให้ AI ลบรายงานหรือหลักฐานเองเพราะเห็นสถานะเสร็จ
- การนำไฟล์ออกจากดัชนีหรือ Git revision ปัจจุบันไม่เท่ากับลบทุกสำเนาหรือประวัติ Git การลบถาวรเป็นงานแยกที่ต้องได้รับอนุมัติโดยชัดเจน

ยังไม่ต้องเพิ่ม database, vector store, subscription หรือ API เพื่อเก็บคลังนี้ ค่า license/cloud เพิ่ม 0 บาทจากการใช้ Markdown และ Git ที่มีอยู่ ต้นทุนดูแลคือการตรวจสถานะและปรับลิงก์เมื่อมีการเปลี่ยนแปลง ไม่ต้องกดยืนยันรายวัน

## ขอบเขตการเผยแพร่

repo นี้เป็น public จึงเก็บเฉพาะข้อสรุปที่เหมาะกับการเผยแพร่ ไม่เก็บบัญชีทดสอบ, PIN, token, เอกสารที่ผูกกับบุคคล, ลิงก์ไฟล์เฉพาะรายการ หรือขั้นตอนตรวจปัญหาความปลอดภัยของระบบภายนอก

รายงานเต็ม E-Office และ PDF ยังเก็บนอก repo ในเครื่องผู้ตรวจที่ `D:/tmp/eoffice-audit-20261026/` รายงานข้อความคือ `REPORT-TH.md` และ PDF อยู่ใน `output/pdf/` ตำแหน่งนี้ไม่ถูก Git sync ไปเครื่องอื่น และไฟล์ใน tmp ไม่ใช่สำรองถาวร เจ้าของระบบควรเก็บสำเนาในพื้นที่ที่ตนควบคุมและอนุญาต ห้ามอัปโหลดฉบับเต็มไป repo public โดยอัตโนมัติ
