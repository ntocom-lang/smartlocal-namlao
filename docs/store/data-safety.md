# ร่างคำตอบแบบฟอร์ม Data safety (Google Play) — แอป "ท้องถิ่นของเรา"

ร่างเมื่อ 2569-11-03 · **ยังไม่ได้ส่งเข้า Play Console** (ต้องมีบัญชีองค์กรก่อน) · ที่มาของข้อมูลคือ [นโยบายความเป็นส่วนตัว](../../src/lib/privacyPolicy.js) ข้อ 2–8
ถ้านโยบายเปลี่ยน ต้องกลับมาแก้ไฟล์นี้และแบบฟอร์มให้ตรงกัน — แบบฟอร์มที่ขัดกับพฤติกรรมจริงของแอป Google ถือเป็นการละเมิดนโยบาย

กติกาของ Google อ่านจากหน้าทางการแล้ว: [Provide information for Google Play's Data safety section](https://support.google.com/googleplay/android-developer/answer/10787469)

## คำตอบระดับบนสุด
| ข้อ | คำตอบ | เหตุผล |
|---|---|---|
| แอปเก็บหรือแชร์ข้อมูลประเภทที่ต้องแจ้งหรือไม่ | **ใช่** | ข้อมูลบัญชี คำร้อง คำขอ ตำแหน่ง ฯลฯ ส่งไปเก็บที่เซิร์ฟเวอร์ |
| เข้ารหัสระหว่างส่งทั้งหมดหรือไม่ | **ใช่** | HTTPS ตลอด (นโยบายข้อ 8) |
| ผู้ใช้ขอลบข้อมูลได้หรือไม่ | **ใช่** | ลบบัญชีเองได้ในแอป (หน้าบัญชีของฉัน) และที่เว็บ `https://app.rk-networks.com/account/delete` — ลบบัญชีและโปรไฟล์ทันที ส่วนคำร้อง/คำขอ/การจองเป็นเอกสารราชการ เก็บไว้แต่ไม่ผูกกับบัญชี (นโยบายข้อ 6) ให้ระบุข้อนี้ในช่อง "ข้อมูลที่เก็บไว้" ของหน้าลบข้อมูล |
| มีโฆษณาหรือ SDK ติดตามของบุคคลภายนอกหรือไม่ | **ไม่มี** | นโยบายประกาศไว้และมีเทสต์ตรึง (`tests/privacy-policy.test.mjs`) |
| ข้อมูลที่ประมวลผลแล้วทิ้งทันที (ephemeral) | **ไม่มี** | ทุกอย่างบันทึกลงฐานข้อมูล |

## ประเภทข้อมูลที่ต้องติ๊ก "เก็บ (Collected)"
คอลัมน์ "ต้องมี/ไม่บังคับ": ไม่บังคับ = ใช้แอปต่อได้โดยไม่กรอก (Google ให้ตอบ "ไม่บังคับ" ได้เฉพาะเมื่อผู้ใช้ทุกคนเลือกได้จริง) — **ต้องเปิดฟอร์มจริงตรวจอีกรอบก่อนกรอก**

| หมวดของ Google | ข้อมูลในระบบ | ต้องมี/ไม่บังคับ | วัตถุประสงค์ที่เลือก |
|---|---|---|---|
| ข้อมูลส่วนบุคคล › ชื่อ | ชื่อ-นามสกุลในบัญชี คำร้อง คำขอ การจองรถ | บังคับ (สร้างบัญชี/ยื่นเรื่อง) | การทำงานของแอป · การจัดการบัญชี |
| ข้อมูลส่วนบุคคล › เบอร์โทรศัพท์ | บัญชี (ใช้เป็นชื่อผู้ใช้) คำร้อง คำขอ จองรถ | บังคับ (สมัครด้วยเบอร์) | การทำงานของแอป · การจัดการบัญชี |
| ข้อมูลส่วนบุคคล › อีเมล | จาก LINE/Google ถ้ามี | ไม่บังคับ | การจัดการบัญชี |
| ข้อมูลส่วนบุคคล › ที่อยู่ | บัญชี คำขอบริการ | ไม่บังคับ | การทำงานของแอป |
| ข้อมูลส่วนบุคคล › รหัสผู้ใช้ (User IDs) | รหัสบัญชีภายในระบบ | บังคับ | การทำงานของแอป · การจัดการบัญชี |
| ข้อมูลส่วนบุคคล › ข้อมูลอื่นๆ | เลขบัตรประชาชน (ถ้ากรอก) | ไม่บังคับ | การทำงานของแอป |
| ตำแหน่ง › ตำแหน่งที่แน่นอน | พิกัดหมุดในคำร้อง/จุดรับผู้ป่วย · ตำแหน่งเครื่องเมื่อกดอนุญาต | ไม่บังคับ | การทำงานของแอป |
| สุขภาพและฟิตเนส › ข้อมูลสุขภาพ | ความต้องการเคลื่อนไหว (รถเข็น/เปล) ในการจองรถผู้ป่วย · อาการในคำร้องเรื่องกลิ่น | ไม่บังคับ | การทำงานของแอป |
| รูปภาพและวิดีโอ › รูปภาพ | รูปโปรไฟล์ รูปแนบคำร้อง | ไม่บังคับ | การทำงานของแอป |
| ไฟล์และเอกสาร | เอกสารแนบคำขอบริการ | ไม่บังคับ | การทำงานของแอป |
| กิจกรรมในแอป › เนื้อหาอื่นที่ผู้ใช้สร้าง | รายละเอียดคำร้อง รีวิวสถานที่ท่องเที่ยว คำตอบแบบสำรวจ | ไม่บังคับ | การทำงานของแอป |
| รหัสอุปกรณ์หรือรหัสอื่น | ข้อมูลอุปกรณ์สำหรับส่งแจ้งเตือน (เมื่อเปิดรับ) | ไม่บังคับ | การทำงานของแอป |

ไม่มีในระบบ จึง **ไม่ติ๊ก**: ข้อมูลการเงิน (ไม่มีการชำระเงินในแอป — คำขอเรื่องภาษี/ค่าธรรมเนียมเป็นการสอบถามยอด), ข้อความ/SMS, รายชื่อติดต่อ, ปฏิทินในเครื่อง, เสียง, ประวัติการท่องเว็บ, รายชื่อแอปที่ติดตั้ง

## ข้อที่ไม่แน่ใจ — ต้องให้เจ้าของระบบ/DPO ตัดสินก่อนกรอก
1. **ข้อมูลใช้งานระบบ (IP, ชนิดอุปกรณ์/เบราว์เซอร์, เวลาเข้าสู่ระบบ ตามนโยบายข้อ 2 บรรทัดสุดท้าย) และสถิติจำนวนครั้งที่เปิดหน้า** — Google ไม่มีช่อง "IP" ตรงๆ ใกล้สุดคือ "รหัสอุปกรณ์หรือรหัสอื่น" และ "กิจกรรมในแอป › การโต้ตอบกับแอป" (สถิติเป็นจำนวนต่อหน้า ไม่ระบุตัวบุคคลตามนโยบาย) ผมเสนอให้ **แจ้งไว้ทั้งสองช่อง** วัตถุประสงค์ "ความปลอดภัย/ป้องกันการทุจริต" และ "วิเคราะห์" เพราะแจ้งเกินปลอดภัยกว่าแจ้งขาด
2. **"แชร์ (Shared)" กับบุคคลที่สาม** — Google ไม่นับเป็นแชร์เมื่อส่งให้ผู้ให้บริการที่ประมวลผลแทนผู้พัฒนา ผู้พัฒนาจึงตอบ "ไม่แชร์" ได้ก็ต่อเมื่อสถานะ "ผู้ประมวลผลแทน อปท." ตรงกับสัญญา/ข้อตกลงจริง (นโยบายระบุว่า อปท. เป็นผู้ควบคุมข้อมูล) **ค้างให้ DPO ยืนยัน + ต้องมีข้อตกลงประมวลผลข้อมูล (DPA) ระหว่างผู้พัฒนากับ อปท.**
3. **พิกัดที่ส่งตรงจากเครื่องผู้ใช้ไป Open-Meteo (พยากรณ์อากาศ) และ OpenStreetMap/Esri (แผนที่ แปลงพิกัดเป็นชื่อสถานที่)** — ผู้ใช้กดอนุญาตตำแหน่งเอง แต่ข้อมูลออกไปยังบุคคลที่สาม ต้องตัดสินว่านับเป็น "การแชร์ตำแหน่ง" หรือไม่ ผมเอนไปทาง **ติ๊กแชร์ตำแหน่งกับบริการแผนที่/อากาศ** เพราะตอบผิดฝั่งแชร์น้อยเกินเสี่ยงกว่า
4. **รถรับ-ส่งผู้ป่วยส่งข้อมูลให้สถานพยาบาลปลายทาง** เป็นการเปิดเผยตามบริการที่ อปท. จัดและขอความยินยอมแยกไว้ในขั้นจอง (นโยบายข้อ 3–4) ไม่ใช่การส่งของแอปเอง — ต้องให้ DPO ยืนยันว่าตอบแบบฟอร์มอย่างไร
5. **แอปเป็น TWA (Chrome เปิดเว็บ) ไม่มี SDK ของผู้พัฒนาฝังในแอป** — กติกา Google นับข้อมูลที่เก็บผ่าน WebView ที่แอปควบคุม ส่วน TWA ไม่อยู่ในหน้าที่ผมอ่านจึง **ยืนยันไม่ได้ว่านับหรือไม่** ผมตอบตามพฤติกรรมจริงของเว็บทั้งหมด (ปลอดภัยกว่า)
6. **ข้อมูลที่ Google/LINE ส่งกลับมาตอนล็อกอิน (ชื่อ รูป อีเมล)** เป็นข้อมูลที่แอปรับมาและเก็บ จึงรวมอยู่ในแถวชื่อ/อีเมล/รูปภาพข้างบนแล้ว

## หลังกรอกแล้ว
- ดูหน้า "Data safety" ตัวอย่างใน Play Console เทียบกับตารางนี้ทีละแถว
- ทุกครั้งที่เพิ่มโมดูลที่เก็บข้อมูลชนิดใหม่ ให้กลับมาแก้ไฟล์นี้ + นโยบาย + แบบฟอร์มพร้อมกัน
