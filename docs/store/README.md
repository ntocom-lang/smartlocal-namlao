# ชุดเอกสารส่งแอป "ท้องถิ่นของเรา" ขึ้น Google Play

อัปเดต 2569-11-03 · ฝั่งโค้ด/เว็บ/ภาพ/ข้อความของ Android พร้อมแล้ว **ที่ยังส่งไม่ได้เพราะต้องรอเจ้าของระบบ** (ดู "ต้องทำก่อนส่ง" ด้านล่าง)
iOS (App Store) ยังไม่เริ่ม — ต้องมีบัญชี Apple ก่อน และต้องเขียนโค้ดห่อแอปเพิ่ม

## ไฟล์ในชุดนี้
| ไฟล์ | ใช้ทำอะไร |
|---|---|
| [listing.json](listing.json) | ข้อความหน้าสโตร์ ไทย/อังกฤษ (ชื่อ คำอธิบายสั้น/เต็ม บันทึกรุ่น) + ลิงก์ที่ต้องกรอก — ตรวจความยาวด้วย `npm run test:store-listing` |
| [data-safety.md](data-safety.md) | ร่างคำตอบแบบฟอร์ม Data safety + ข้อที่ต้องให้ DPO ตัดสิน |
| `npm run store:assets` | สร้างภาพหน้าจอ 8 ภาพ (1080×1920) + ภาพกราฟิกเด่น 1024×500 ไปที่ `D:\tmp\store-assets` (ถ่ายจากเดโมบน production แบบอ่านอย่างเดียว) |
| `public/icons/icon-512x512.png` | ไอคอนแอป 512×512 ตามเกณฑ์ Google |
| `npm run twa:build` | สร้างไฟล์ AAB ที่ส่งขึ้น Play (ผลที่ `D:\tmp\twa-build\app-release-bundle.aab`) |
| `npm run twa:publish` | เอา APK ที่ build แล้วขึ้นหน้า `/download` (ดู "ช่องทางทดลองก่อนขึ้นสโตร์") |

## ช่องทางทดลองก่อนขึ้นสโตร์ (ไม่ต้องรอบัญชี Play/Apple)
หน้า `https://app.rk-networks.com/download` ให้ อปท./ผู้บริหาร/ผู้ทดลองติดตั้งแอปได้ทันที: Android โหลดไฟล์ APK ตรง · iPhone เพิ่มลงหน้าจอหลัก (ไม่มี APK บน iOS) · มี QR ให้สแกนส่งต่อ
- บัญชีใช้ชุดเดียวกับเว็บ (อยู่ที่ฐานข้อมูลกลาง) ไม่ต้องสมัครใหม่ · การจำล็อกอินอยู่ในเครื่องแยกตามช่องทาง จึงเขียนในหน้าว่า "อาจต้อง" ล็อกอินซ้ำ — ยังไม่ได้ทดสอบกับมือถือจริง
- **ออก APK ใหม่ (เช่น มี อปท. ใหม่ หรือเปลี่ยนชื่อแอป):** เพิ่ม `APP_VERSION.code` ใน `scripts/twa-build.mjs` → `npm run twa:build` → `npm run twa:publish` (ตรวจลายเซ็น/package/เวอร์ชันให้ แล้วเขียนไฟล์ + ค่า SHA-256 ที่หน้าเว็บแสดง) → commit `public/downloads/` + `src/lib/appDownload.js` เปิด PR
- ⚠️ APK ที่แจกตรงเซ็นด้วย upload key ถ้าตอนสร้างแอปใน Play ไม่เลือกใช้กุญแจเดิมเป็น app signing key ผู้ที่ลงตรงจะอัปเดตข้ามไปรุ่นจาก Play ไม่ได้ ต้องถอนแล้วลงใหม่ — **ยังไม่ได้ยืนยันกับหน้าทางการว่า Play ให้ใช้กุญแจเดิม** (เปิดดูตอนสร้างแอปในคอนโซล)
- ไฟล์ APK อยู่ใน git (~1 MB ต่อรุ่น) เพราะเสิร์ฟจากโดเมนเดียวกันด้วย Cloudflare Workers Assets ฟรี — ออกรุ่นใหม่ไม่บ่อย

**ยังไม่ได้เปิดหน้าทางการดูรายการคำถามจริงของ:** แบบประเมินเรตติ้งเนื้อหา (IARC), คำประกาศแอปภาครัฐ (Government apps), คำประกาศแอปสุขภาพ, รายการหมวดหมู่ที่เลือกได้ — เจอตอนกรอกในคอนโซลให้ตอบตามจริงและส่งคำถามมา ผมช่วยตรวจ
จุดที่ต้องระวังตอนตอบ: ผู้ใช้โพสต์เนื้อหาได้ (คำร้อง/รีวิว) · แชร์ตำแหน่ง · มีฟีเจอร์เกี่ยวกับสุขภาพ (รถรับ-ส่งผู้ป่วย) · พัฒนาแทนหน่วยงานรัฐ

⚠️ ภาพ 02 (หน้าแรก) มีรูปมือถือในแบนเนอร์ของเดโม ซึ่งเป็นส่วนของหน้าจอจริง แต่กติกาภาพของ Google ห้ามภาพที่มีคนถือ/กดเครื่อง ถ้าผู้ตรวจติงให้เปลี่ยนแบนเนอร์ของ อปท. สาธิตแล้วรัน `npm run store:assets` ใหม่

### ช่อง "สิทธิ์เข้าถึงแอป (App access)" สำหรับผู้ตรวจ Google
ข้อความที่แนะนำให้กรอก (ไม่ใส่รหัสผ่านใน repo — กรอกในคอนโซลตรงๆ):
> เปิดแอปได้โดยไม่ต้องล็อกอิน เลือก "เทศบาลตำบลสาธิต" ที่ส่วน "ทดลองใช้งาน" ท้ายรายการหน่วยงาน (เรื่องที่แจ้งในหน่วยงานสาธิตไม่ถึงหน่วยงานจริง) ฟีเจอร์ที่ต้องเข้าสู่ระบบ: ติดตามคำร้อง/คำขอ บัญชีของฉัน ลบบัญชี — ใช้บัญชีทดสอบ: ชื่อผู้ใช้ `<<เจ้าของระบบสร้างบัญชีสาธิตแล้วกรอก>>` รหัสผ่าน `<<กรอกในคอนโซล>>`

## ขั้นตอนส่งจริง (เมื่อพร้อม)
1. สร้างแอปในคอนโซลด้วย package ข้างบน เปิดใช้ Play App Signing
2. อัปโหลด AAB (`app-release-bundle.aab`) ที่ช่องทดสอบภายใน (internal testing) ก่อน — Google ยกเว้นแบบฟอร์ม Data safety ให้แอปที่อยู่ในช่องทดสอบภายในเท่านั้น (ตรวจจากหน้าทางการ 2569-11-03)
3. **คัดลอกลายนิ้วมือ SHA-256 ของ "App signing key" จากคอนโซล ใส่ใน `ANDROID_CERT_FINGERPRINTS` ที่ `worker/storeApp.js` แล้ว merge/deploy** — ลืมข้อนี้ แอปจากสโตร์จะมีแถบที่อยู่เว็บทุกหน้า (ลายนิ้วมือ upload key ใส่ไว้แล้ว)
4. ทดสอบแอปที่ลงจาก Play จริงบนมือถือ: ไม่มีแถบที่อยู่ · ล็อกอิน LINE/Google กลับเข้าแอป · แจ้งเตือน · เปลี่ยนหน่วยงาน
5. กรอกหน้าข้อมูลแอป ภาพ แบบฟอร์ม แล้วส่งตรวจ ทุกครั้งที่อัปโหลดใหม่ต้องเพิ่ม `APP_VERSION.code` ใน `scripts/twa-build.mjs`
6. มี อปท. ใหม่ = เพิ่มชื่อโดเมนในแอป → ออกเวอร์ชันใหม่ (`npm run twa:build` ดึงรายชื่อจากฐานเอง)

**เงื่อนไขทดสอบก่อนเผยแพร่:** หน้าทางการ ([answer/14151465](https://support.google.com/googleplay/android-developer/answer/14151465)) ระบุเฉพาะ *บัญชีบุคคลที่สร้างหลัง 13 พ.ย. 2023* ว่าต้องทดสอบแบบปิดกับผู้ทดสอบ ≥ 12 คน ต่อเนื่อง 14 วัน — **ไม่พูดถึงบัญชีองค์กร** ยืนยันไม่ได้ว่ายกเว้นหรือไม่ ให้ดูในคอนโซลตอนสมัคร

## ต้องทำก่อนส่ง (ผมทำแทนไม่ได้)
1. ชื่อนิติบุคคลผู้พัฒนา + อีเมลติดต่อ → เติม `PLATFORM_DEVELOPER` ใน `src/lib/platform.js` (นโยบาย/หน้าสโตร์/ผู้ใช้ต้องเห็นชื่อเดียวกัน)
2. เลข D-U-N-S + สมัครบัญชีองค์กร Play (ค่าสมัคร US$25 ครั้งเดียว)
3. หนังสืออนุญาตลงนามจาก อปท. ทุกแห่ง ระบุชื่อแอป package และผู้พัฒนา ส่งถึง Google
4. บัญชีสาธิตสำหรับผู้ตรวจ (ข้อความด้านบน)
5. DPO ตรวจนโยบายและตอบข้อที่ค้างใน data-safety.md + ข้อตกลงประมวลผลข้อมูลระหว่างผู้พัฒนากับ อปท.
6. ทดสอบ APK บนมือถือจริง (โดยเฉพาะ LINE/Google login)
