## หลักฐานและข้อจำกัด

- รายงานสาธารณะ: https://www.hydro-1.net/Data/HD-04/houly/water_today_search.php
- บัญชีสถานี: https://www.hydro-1.net/Data/STATION/station_1.html — Y.20 แม่น้ำยม ต.เตาปูน อ.สอง; Y.38 น้ำแม่คำมี ต.ตำหนักธรรม อ.หนองม่วงไข่
- API ที่หน้าเว็บดังกล่าวใช้อยู่: https://hydro1.ddns.net/main/information_6/water_today_search_json.php ผ่าน JSONP; ใช้ GET station01/datestart/dateend/callback
- ทดลองอ่าน Y.20 และ Y.38 สำเร็จ ทั้งที่ตั้ง วันที่ เวลา ระดับน้ำ และน้ำไหลผ่าน; ไม่ใช่ API ที่มีสัญญารับรองความพร้อมใช้งาน
- ระบบไม่ใช้ `level_limit` หรือ `dischg_limit` ตัดสินสีเตือน: ต้องยืนยันความหมายและรุ่นเกณฑ์ก่อน ค่าอ้างอิงต้นทางไม่จำเป็นต้องตรงกับเกณฑ์ของพื้นที่ปลายทาง
- ระดับน้ำ Hydro-1 แสดงเป็นค่าที่เสาวัดสถานี ไม่ใส่ลง `waterlevel_msl` ของ ThaiWater และไม่หักลบค่าข้ามแหล่ง
- ข้อมูลของสถานีไม่ได้ยืนยันความลึกน้ำท่วม ระยะเวลาน้ำเดินทาง หรือความปลอดภัยของทุกหมู่บ้าน
- รายการจับคู่ราย อปท. อยู่ใน `src/lib/hydroHourly.js`; พื้นที่ใหม่ต้องตรวจความสัมพันธ์กับทางน้ำ ไม่เลือกจากระยะใกล้อย่างเดียว
- น้ำแม่คำมีไหลจากทิศตะวันออกไปตะวันตกเฉียงใต้ผ่านตำหนักธรรมก่อนบรรจบแม่น้ำยม ขณะที่ทางน้ำแม่คำปอง/แม่ลายของน้ำเลาแยกกัน; ระดับน้ำ Y.38 จึงไม่ใช่ตัวแทนสถานการณ์น้ำในน้ำเลา: https://water.rid.go.th/hydhome/hydmag/journal/June-8-96-64.pdf และ https://www.opsmoac.go.th/phrae-strategic-files-451091791794

## การทำงานและค่าใช้จ่าย

ใช้ Worker เดิม รับเฉพาะ Y.20/Y.38, timeout 10 วินาที, ตรวจชื่อ/ที่ตั้งตรงสถานี, JSONP แปลงด้วย JSON.parse โดยไม่ execute, กรองเวลาอนาคตและค่าผิดรูปแบบ

ดึงย้อนหลังจากต้นทางเมื่อเปิดหน้าและ cache อายุ 1 ชั่วโมงต่อสถานีที่ edge (cache แยกตามศูนย์ข้อมูล Cloudflare ไม่ใช่ฐานกลางถาวร) เก็บสำเนาสำรองใน cache ไม่เกิน 24 ชั่วโมงหากต้นทางล่ม หน้าเว็บตรวจซ้ำทุก 5 นาทีเฉพาะเมื่อมองเห็น ไม่มี cron หรือฐานข้อมูลใหม่ และไม่มีการเก็บประวัติถาวร

ใช้ Free Tier เดิม ไม่เพิ่มบริการ/API เสียเงิน ไม่เปิดแพ็กเกจใหม่ ภาระดูแลคือแก้ตัวอ่านเมื่อต้นทางเปลี่ยนรูปแบบและตรวจ mapping เมื่อเพิ่ม อปท. หากต้นทางล่ม ผู้ใช้เห็นคำเตือนและเปิดรายงานต้นทางได้ ผู้ดูแลระบบแก้ adapter ได้จุดเดียว เจ้าหน้าที่ไม่ต้องกรอกค่ารายวัน
